
# 설비 고장 분석기
설치·사용 설명서
v1.5.0  |  Excel 분석파일 + PDF 최종보고서
핵심 변경: 고장 분류 엔진과 규칙을 다시 만들어 검토필요가 크게 줄었습니다. 검토필요로 남는 행에는 사유와 후보가 표시되며, 행별 수동 보정은 바꾼 항목만 저장하고 언제든 해제할 수 있습니다.

## 두 결과파일의 역할
파일 | 주요 용도
Excel (.xlsx) | 설비별·유형별 상세 집계, 원기록 확인, 필터링, 추가 분석
PDF (.pdf) | 종합 요약, 주요 고장, 월별 추이, 설비별 원형 차트, 관리 검토사항

## 무엇을 더블클릭하나요?
상황 | 실행할 파일
Python이 있는 현재 PC | ZIP 압축을 모두 푼 뒤 START.bat 더블클릭
Python 없는 PC용 EXE 준비 | 준비된 Windows PC에서 BUILD_EXE.bat 실행
빌드된 EXE를 받은 일반 PC | EquipmentFailureAnalyzer.exe 더블클릭
배포본의 기준은 Python 소스입니다. 폴더에 EquipmentFailureAnalyzer.exe가 함께 있더라도 BUILD_EXE.bat으로 v1.5.0 소스에서 다시 빌드한 파일만 최신 버전입니다.
설치 순서: 1장 Python 있는 PC / 2장 Python 없는 PC / 3장 두 파일 생성 / 4장 검토필요 처리 / 5장 업데이트·문제 해결.

# 1. Python이 있는 현재 PC

## STEP 1  압축 풀기
배포 ZIP을 바탕화면 등 쓰기 가능한 폴더에 모두 압축 풀기합니다. ZIP 안에서 파일을 직접 실행하지 마세요.
START.bat, BUILD_EXE.bat, USER_GUIDE.pdf와 source 폴더가 같은 위치에 있어야 합니다.

## STEP 2  START.bat 실행
START.bat을 더블클릭합니다. 최초에는 설치된 Python을 확인한 뒤 source/.venv에 전용 실행환경과 필요한 라이브러리를 설치합니다. 설치가 끝나면 프로그램 창이 열립니다.
이 배포본의 소스 실행 대상: Python 3.11~3.13, 64비트 Windows. 다른 버전/32비트인 경우 사내 IT에 지원 버전 설치를 문의하세요.

## STEP 3  다음 실행부터
다음부터도 START.bat만 실행합니다. 설치 후 분석·보고서 생성은 외부 API나 웹서버 없이 동작합니다.

## 인터넷 접속이 차단된 경우
최초 설치에는 승인된 패키지 접근 또는 사전 준비된 wheels 묶음이 필요합니다. 5장을 참조하세요.

# 2. Python이 없는 일반 PC
일반 PC에 START.bat만 복사하면 실행되지 않습니다. 먼저 Python이 있는 Windows PC에서 실제 EXE를 만들어야 합니다.

## STEP 1  현재 Windows PC에서 확인
START.bat으로 v1.5.0이 열리는지 확인합니다. 샘플 파일로 Excel과 PDF가 모두 생성되는지 확인한 뒤 프로그램을 닫습니다.

## STEP 2  BUILD_EXE.bat 실행
BUILD_EXE.bat을 더블클릭합니다. 빌드용 패키지 설치와 테스트 후 PyInstaller로 EXE를 생성합니다. DONE 메시지와 새로 생성된 파일을 확인하세요.
생성 위치: START.bat과 같은 폴더의 EquipmentFailureAnalyzer.exe. 중간에 실패했다면 예전 EXE를 최신 버전으로 간주하지 마세요.

## STEP 3  복사·실행
생성된 EXE를 현재 PC에서 시험 실행한 뒤 승인된 이동 방법으로 대상 Windows PC에 복사합니다. 대상 PC에서는 EquipmentFailureAnalyzer.exe를 더블클릭합니다.
일반 PC에는 소스 폴더나 .venv를 복사하지 않습니다. 기존 설비명·분류 설정은 필요 시 별도로 이전합니다.
보안 차단 시 보안을 끄지 말고 IT 승인 절차를 따르세요.

# 3. Excel + PDF 두 파일 생성

## STEP 1  입력파일·설비명
Excel을 드래그 앤 드롭하거나 [파일 찾아보기]로 선택합니다. [설비명 변환 설정]에서 코드별 보고서 이름을 입력하세요. IF18115 -> VITAL#2는 초기 예시입니다.
설비명은 입력을 잠시 멈추거나 창을 닫을 때 마지막 값으로 자동저장됩니다. 이름을 넣지 않은 코드는 보고서에 코드 그대로 표시됩니다.

## STEP 2  컬럼 매핑 (필요할 때만)
MES 내보내기 파일은 제목 행과 컬럼을 자동으로 찾습니다. 자동 매핑이 틀리면 [컬럼 매핑]에서 고칩니다.
고친 매핑은 같은 제목 행을 가진 파일에 다음부터 자동 적용됩니다. 매핑을 바꾸면 이미 저장한 수동 보정도 새 매핑에 맞춰 옮겨집니다.

## STEP 3  보고서 설정 (선택)
[보고서 설정]에서 PDF의 제목, 부서, 작성자, 추가 의견을 입력하고 [저장]을 누릅니다. 빈 항목은 생략하며, 제목은 기본값을 사용합니다.

## STEP 4  [Excel + PDF 생성]
가져온 시트·제목 행·분석기간·집계 범위를 확인한 뒤 [Excel + PDF 생성]을 누릅니다. Excel의 저장 위치와 파일명을 선택하면 PDF도 같은 폴더에 생성됩니다.
지정 예시 | 실제 생성 결과
분석결과.xlsx | 분석결과.xlsx, 분석결과_최종보고서.pdf
완료 후 [Excel 열기], [PDF 열기], [결과 폴더]를 사용합니다. 두 파일은 최신 설정으로 다시 집계한 동일 결과를 사용합니다.

## 보고서 읽는 기준
설비별 원형 차트의 100%는 해당 설비의 전체 분석 기록 건수입니다. PDF는 상위 5개 + 기타를 표시하며, 전체 유형은 Excel에서 확인합니다. 미분류도 분모에 포함됩니다.
설비·라인·유형·교차·기간별 분석표는 정지시간 합계 내림차순입니다. 추이 그래프는 날짜순을 유지합니다. [큰 값순 정렬]을 누르면 화면의 기본 정렬을 복원합니다.

# 4. 검토필요 처리

## 무엇이 검토필요가 되나요?
사유 | 의미
미분류 | 비고에서 부품과 증상을 찾지 못함. 분류 규칙 보완 또는 행 수정으로 확정
복수 유형 후보 | 서로 다른 부품이 함께 기록되어 하나를 근거 있게 고를 수 없음 (예: 가이드 및 후크 조정)
정지시간·일자 이상 | 정지시간 없음/형식 오류, 일자 없음, 종료가 시작보다 이름, 입력값과 시작·종료 차이 초과
고장대상 미기재 | 설비 분석 기준이 '고장대상 설비'일 때만 검토필요. 다른 기준에서는 참고 정보로만 표시
검토필요는 집계에서 빠진 행이 아닙니다. 건수·정지시간에는 포함되고, 복수 후보는 임시 1순위 유형으로 집계됩니다.

## 분류 방식
비고 문장을 구절로 나누고, 부품(context) 뒤 가까이 나온 증상(symptom)만 짝지어 분류합니다. 다른 부품명이 나오면 앞 부품의 증상 탐색은 거기서 끝납니다.
표기 차이(실러/씰러, 벨브/밸브, 컨베이어/컨베어 등)는 정규화하고, 문장 끝이 잘린 기록(후크 교 -> 후크 교체)은 복원합니다.
여러 규칙이 맞으면 다음 근거가 있을 때만 자동 선택하고, 분류 근거 열에 '자동선택: 사유'를 남깁니다.
근거 | 예
부품 규칙 우선 | '롤러부 파손'은 부위 미기재 파손이 아니라 롤러
복합명사 중심어 | '실린더 센서 교체'는 센서
교체 부품 우선 | '게이트 작동불량 솔밸브 교체'는 솔밸브
원인 표현 | '정전 발생으로 냉동기 다운'은 전원
MES 소분류 일치 | 근거가 대등할 때 작업자가 고른 컨트롤/기계/공압/냉동파트와 맞는 후보
근거가 없으면 검토필요로 남기고 모든 후보 규칙을 표시합니다. 원인을 확정하는 기능이 아니라 기록된 부품·증상 기준의 분류입니다.

## 행 수정 (선택 기록 수동 수정)
고장 상세 또는 검토필요 탭에서 행을 선택하고 [선택 행 수동 수정]을 누릅니다. 창에는 검토 사유, 수정 방법, 분류 근거와 후보, 저장된 보정 내역이 표시됩니다.
바꾼 항목만 저장됩니다. 정지시간이나 일자만 고치면 분류는 저장되지 않으므로 복수 후보 표시가 그대로 남습니다.
현재 분류를 그대로 확정하려면 '위 대·중·소분류를 사용자확정으로 저장'을 체크합니다. 분류 칸을 고치면 자동으로 체크됩니다.
저장한 값을 지우고 저장하면 그 항목만 해제되고, [수동 보정 해제]를 누르면 그 기록의 보정이 모두 해제됩니다. 저장 후 자동으로 다시 분석하며, Excel/PDF는 다시 생성해야 반영됩니다.

## 분류 규칙 편집
[분류기준 관리]에서 규칙을 추가·수정합니다. role 열: component(부품 규칙), fallback(부품명이 없을 때만 쓰는 부위 미기재 규칙), override(작업자 조작 등 원인 표현 규칙).
context와 symptom은 정규식이며 공백을 뺀 문장에 적용됩니다. symptom이 '.'이면 context만 나와도 일치합니다.

# 5. 업데이트·문제 해결

## 기존 설정 유지와 자동 병합
프로그램을 닫고 새 ZIP을 새 폴더에 푼 뒤 START.bat을 실행하세요. 동일 Windows 사용자의 아래 설정 폴더를 삭제하지 않으면 설비명과 설정이 유지됩니다.
%LOCALAPPDATA%\EquipmentFailureAnalyzer\config
새 버전 첫 실행 시 기본 분류 규칙·표기 정규화·설비군·설정을 자동 병합합니다. 직접 수정하지 않은 기본값은 새 버전으로 바뀌고, 직접 수정·추가·삭제한 규칙은 그대로 둡니다. 병합 전 파일은 config\backup\날짜_시각 폴더에 백업되며 상태 표시줄에 결과가 표시됩니다.
다른 PC로 이전할 때는 양쪽 프로그램을 닫고 config를 백업한 뒤 이전하세요. 설비명: equipment_names.json / 수동 보정: manual_overrides.json / 컬럼 매핑: column_overrides.json / PDF 설정: final_report.json.

## 인터넷 없이 설치
같은 Windows·Python 버전/비트의 준비 PC에서 source/prepare_wheels.bat을 실행해 필요한 파일을 모읍니다. wheels 폴더 전체를 대상 소스의 source/wheels에 옮긴 뒤 START.bat을 실행합니다. 부분 패키지만 있으면 설치가 실패합니다.
증상 | 조치
PDF 모듈 없음 | START.bat 또는 source/setup.bat을 실행해 reportlab 설치. 오프라인이면 새 wheels 준비
저장 실패 | Excel과 PDF를 모두 닫고 다른 이름으로 저장. 저장 폴더 권한 확인
한글 PDF 글꼴 오류 | Windows의 맑은 고딕 설치 확인. 필요 시 final_report.json의 font_path에 승인된 한글 TTF 경로 지정
분류가 예전과 다름 | v1.5.0 규칙으로 병합됨. 이전 규칙은 config\backup 폴더에 있음
제목/설비명이 예전 값 | 설정 저장 후 [Excel + PDF 생성]으로 새로 출력. 과거 파일은 자동 변경되지 않음
오류 로그: %LOCALAPPDATA%\EquipmentFailureAnalyzer\logs\application.log
확인 범위: 자동 테스트 115개 통과(GUI 테스트 포함). 실제 MES 파일(고장 414건)로 Excel·PDF 생성 확인. EXE 빌드·다른 PC 실행은 BUILD_EXE.bat으로 별도 확인이 필요합니다.
공식 기술 참고: https://pyinstaller.org/en/stable/usage.html
