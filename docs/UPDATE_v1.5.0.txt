v1.5.0 변경점 - 검토필요 최소화 및 오류 수정

[검토필요 감소]  실제 MES 파일(2026-01~10, 고장 414건) 기준 300건 -> 11건
- 고장대상 판정 패턴 수정: '2P I/C'만 인정하던 패턴을 1P/2P/3P 전 라인으로 확장 (300 -> 230)
- 고장대상 미기재는 설비 분석 기준이 '고장대상 설비'일 때만 검토필요. 그 외는 참고 정보 (-> 188)
- 표기 정규화와 잘린 문장 끝 복원 ('후크 교' -> '후크 교체', 실러/씰러, 벨브/밸브 등) (-> 193)
- 분류 엔진: 부품 뒤 가까운 증상만 짝짓고, 근거가 있을 때만 복수 후보를 자동 선택 (-> 153)
- 분류 규칙 29개 -> 67개 (퓨즈·인버터·히터·TC·후크·가이드·에어라인·호스·펌프·씽크탑·WAGO 등) (-> 11)
남은 11건은 두 부품이 함께 적힌 기록(예: 가이드 및 후크 조정)으로, 행 수정에서 확정하세요.

[오류 수정]
- 분류 규칙의 '씌러/씌링/씬/오링' 오타를 '씰러/씰링/씰/오링'으로 수정 (씰러·씰링 기록이 분류되지 않던 문제)
- 행 수정에서 정지시간만 고쳐도 분류가 '사용자확정'으로 바뀌던 문제: 바꾼 항목만 저장
- 저장한 수동 보정을 지울 수 없던 문제: 항목을 비우면 해제, [수동 보정 해제]로 전체 해제
- 컬럼 매핑 수정이 시트를 다시 읽으면 사라지던 문제: 제목 행 기준으로 저장해 다시 적용
- 컬럼 매핑을 바꾸면 기존 수동 보정이 끊기던 문제: 새 기록 ID로 자동 이전
- 보고서 문구 오타('남걁니다'), numpy 지원 중단 경고 제거
- v1.4.0 기능(검토 사유 안내, 일자·정지시간 보정) 테스트 추가

[구버전 실행 차단]
- 같은 PC의 모든 버전이 사용자 설정을 공유하므로, v1.5.0 실행 후 예전 v1.4.0 EXE를 열면 예전 엔진이 새 규칙을 읽어
  검토필요가 344건(복수 후보 320건)으로 늘어나는 문제가 있었습니다.
- 분류 규칙을 v2 형식(rules_v2 시트, 스키마 버전 기록)으로 저장합니다. 예전 프로그램은 "이 분류 규칙은 v1.5.0 이상 전용입니다" 안내 후 멈춥니다.
- 이후 버전이 더 새로운 형식의 규칙을 만들면 이 버전도 분석을 거부하고 최신 버전 실행을 안내합니다.
- BUILD_EXE.bat 결과물에 버전이 붙습니다: EquipmentFailureAnalyzer_v1.5.0.exe

[결과 파일 저장 위치]
- Excel + PDF 저장 창의 기본 위치를 사용자 데이터 폴더(%LOCALAPPDATA%)에서 프로그램 폴더의 output 폴더로 바꿨습니다.
- 프로그램 폴더에 쓸 수 없으면(예: 읽기 전용 위치의 EXE) 예전처럼 %LOCALAPPDATA%\EquipmentFailureAnalyzer\output을 씁니다.

[기존 사용자 설정]
- 새 버전 첫 실행 시 기본 분류 규칙·정규화·설비군·설정을 자동 병합합니다.
- 직접 수정하지 않은 기본값만 새 버전으로 바뀌며, 직접 수정·추가·삭제한 규칙은 그대로 둡니다.
- 병합 전 파일은 %LOCALAPPDATA%\EquipmentFailureAnalyzer\config\backup\날짜_시각 에 백업됩니다.

- EXE는 BUILD_EXE.bat으로 빌드하며, 파일명의 버전으로 구분합니다.
