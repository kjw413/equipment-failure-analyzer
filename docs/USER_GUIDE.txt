
# 설비 고장 분석기
설치·사용·동작 원리 안내서
v1.22.1 · 입력 중 유사 후보 검색 · Excel 분석 파일 + PDF 최종 보고서 + 원본 검토표시 사본
> 이 안내서는 앞부분에 요약을 싣고, 1장부터 설치, 사용 방법, 동작 원리를 자세히 설명합니다.

## 이 프로그램이 하는 일
MES에서 내려받은 '라인 비가동 현황 조회' Excel 파일을 읽어 고장 기록만 골라냅니다. 기록마다 비고를 읽어 어느 부품이 어떻게 고장 났는지 분류하고, 설비·고장 유형·기간별로 건수와 정지시간을 집계합니다. 결과는 세 파일로 나옵니다. Excel 파일에서는 상세 집계와 원본 기록을 확인하고 필터로 더 분석할 수 있습니다. PDF 보고서에는 핵심 요약, 월별 추이, 설비별 원형 차트, 관리 검토사항이 들어 있어 공유하기 좋습니다. 원본 검토표시 사본에는 검토필요 행의 색상과 사유 메모를 추가하며, 입력 원본은 보존합니다.
모든 처리는 이 PC 안에서 끝나며, 외부로 보내는 자료는 없습니다. AI나 학습 기능도 쓰지 않습니다. 분류는 누구나 열어 보고 고칠 수 있는 규칙표를 그대로 따릅니다.

## 처리 순서
단계 | 하는 일 | 예
1. 읽기 | 제목 행을 찾아 열을 맞추고, 빈 행과 합계 행은 건너뜁니다 | 제목 행(7행)을 자동으로 찾음
2. 정리 | 고장 기록을 골라 날짜와 정지시간을 정하고, 제각각인 표기를 통일합니다 | 실러 → 씰러, '후크 교' → '후크 교체'
3. 분류 | 비고에서 부품과 증상을 찾아 최종 유형 하나를 정하거나 검토 후보를 제시합니다 | '근접센서 단선' → 전기·제어 / 근접센서 / 단선
4. 집계 | 설비·라인·유형·월별로 건수를 세고 정지시간을 더합니다 | 설비 A: 12건, 340분
5. 보고서 | Excel(기본 11개 표시 시트, 제품 자료가 있으면 12개), PDF, 원본 검토표시 사본을 한 번에 만듭니다 | output 폴더에 저장

## 고장 유형을 정하는 방법
고장 분야 / 상세설비·모듈 / 부품군 → 세부 부품 / 고장 현상으로 정리하고 조치는 별도 보존합니다. 공개 최종 분류 필드는 고장 분야·상세설비·세부 부품·고장 현상의 네 항목입니다. 부품군은 선택한 부품에서 표시합니다. 한 이력에 대표 분류 하나를 저장합니다. 명확한 단일 고장을 먼저 선택하고, 남은 복수 부품·현상·설비 후보는 원문 고장 또는 완료 조치 근거가 있는 1순위를 대표로 자동 선택합니다. 원문과 모든 후보는 보존하며 의심·대안 등 보호 조건은 검토에 남깁니다.
1순위는 규칙 근거에 따른 순서이며 정확도나 확률이 아닙니다. 대표 자동선택은 다른 실제 고장이 없다는 뜻이 아닙니다. 판정 사유의 1순위 대표 자동선택 표시와 전체 후보를 확인할 수 있습니다.
교체·수리·조정·점검 등은 조치입니다. 단일 부품의 조치만 적힌 기록은 부품과 조치를 자동 보존하고 현상 미기재로 부분분류합니다. 파손이나 마모를 추정하지 않습니다. 차단기 떨어짐은 보호장치 동작이고, 과부하 원인은 원문에 적힌 경우에만 기록합니다. 원본 비가동코드와 담당 부서로 고장 분야를 강제하지 않습니다.
규칙과 맞는 후보가 없으면 비가동코드(중·소)가 비어 있을 때 비가동코드 미기입, 입력돼 있을 때 규칙 미일치로 표시합니다. 판정 상태와 검토 사유는 분류 항목에 넣지 않습니다.

## 추천 후보를 확인하고 단일 분류 확정하기
이번 보완은 수기 피드백 v1.6 시트 2~27행을 기준으로 합니다. 감지 불은 감지 불량, 제품 터는 제품 터짐, 절말 핫멜은 핫멜트로 복원합니다. 기능명·대상명과 절말을 확인하며 컴퓨터·모터·인버터·불꽃 등 온전한 단어는 자르지 않습니다. 사전 기반 띄어쓰기도 복원 후 다시 적용합니다.
열전사는 날인기로, 감지·검출 문맥의 아이마크는 아이마크 센서로 인식합니다. 중분류의 Serac Filler·INGREDIENT FEEDER를 인식하고, 일반 포장기는 중분류의 구체적인 포장기 종류로 보완합니다. 원문에 별도 날인기가 명시된 경우에는 중분류의 포장기로 덮어쓰지 않습니다. 포밍부는 포밍부(포머)로 표시합니다.
터짐·에러코드 발생을 고장 현상으로 추가합니다. WAGO 31 발생 같은 표현은 코드 현상을 보존하되 제어기·PLC 카드 고장으로 추정하지 않습니다. 완료된 부품 교체와 뒤에 따로 적힌 추정 원인은 구분합니다. 핫멜트의 동일 문제처럼 구체적인 현상·부품 없이 과거 문제만 참조하면 상세설비를 보존하고 검토를 유지합니다. 새 규칙의 최소 실행 버전은 v1.18.0입니다.
원문 고장내용/비고 바로 오른쪽에 표준화 후 내용을 나란히 표시합니다. 왼쪽과 오른쪽을 비교해 표준화가 적절한지 먼저 확인한 뒤, 후보와 최종 분류를 검수하세요. 표준화 내용은 실제 현재 분석에 사용한 값이며 읽기 전용입니다. 규칙을 수정했다면 [표준화 + 분석 실행]을 다시 눌러 갱신하세요.
일반적인 보드는 제어기판·카드(종류 미상)로 분류하며 메인보드라고 추정하지 않습니다. 점도 헌팅·이상만 있고 원인 부품이 없으면 검토 대상으로 유지합니다.
1. [검토필요]에서 원문·비가동코드·후보 순위와 근거를 확인합니다.
2. 그리드에서 고장 분야·상세설비·세부 부품·고장 현상을 선택합니다. 네 항목은 독립 선택이며 다른 축을 바꿔도 선택을 유지합니다. 부품군은 종류를 좁혀 찾는 탐색 기준입니다. 후보 비교창에서는 더블클릭 또는 Enter로 후보 하나를 선택할 수 있습니다.
3. 선택은 메모리에 확정 대기로 남습니다. [표준화 + 분석 실행]으로 현재 파일의 대기 분류를 한 번에 확정·저장합니다. 프로그램을 닫으면 미확정 선택은 사라집니다.
4. 검토필요가 남아 있어도 [Excel + PDF 생성]으로 세 파일을 저장합니다. 별첨. 검토품질에서 원문·최종 분류·부품군·조치·후보를 대조합니다. Excel 정답은 규칙 보완 자료이며 프로그램에 자동 반영되지 않습니다.
v3 기준의 기존 수동확정값은 그대로 적용합니다. 이전 스키마 수동확정과 과거 복수 분류는 원본 설정을 변경하지 않고 재검토 후보로 보존합니다. 과거 소분류 교체도 새 고장 현상으로 자동 확정하지 않습니다.
부품별 집계에는 최종 단일 실제 부품만 한 번 포함합니다. 미확정 후보·세부 부품 미기재·제품·자재 대상은 실제 부품 건수에서 제외하고 전체 이력과 정지시간에는 보존합니다. 부품 비율의 분모는 전체 고장기록입니다.

## 화면·보고서의 분류축
항목 | 선택 기준 | 예
고장 분야 | 실제 현상에 따른 분야. 판단 근거가 없으면 분야 미상 | 모터 소손은 전기·제어, 기계적 마모는 기계
상세설비·모듈 | 고장·조치가 연결된 가장 구체적인 설비 | 필러 내부 엔드씰러 히터 쇼트에서 엔드씰러
부품군 → 세부 부품 | 부품군으로 탐색하고 부품 종류를 선택 | 센서·계측 → 광전센서 또는 센서(종류 미상)
고장 현상 | 원문에 명시된 현상 | 손상·파손, 마모, 부식, 보호장치 동작
조치 | 완료된 조치를 별도 보존. 여러 항목 가능 | 교체, 수리·정비, 조정
상세설비 근거가 없으면 상세설비 미상으로 남기며 등록 설비명만으로 실제 고장 설비를 추정하지 않습니다. 본체만 적힌 기록은 세부 부품 미기재로 표시합니다. 종류 미상 항목과 구체 종류를 구별하고, 동일 표기·동의어만 통합합니다. 냉매와 냉각수는 구별합니다.

## 완전 자동분류·부분 자동분류·검토필요
완전 자동분류는 고장 분야·상세설비·세부 부품·고장 현상의 네 항목이 모두 확인된 기록입니다. 부분 자동분류는 대표 분류를 정했지만 일부 항목이 원문에 없는 기록입니다. 자동처리 합계는 완전+부분이며 두 숫자를 합쳐 완전분류로 표시하지 않습니다.
부분분류는 미상·미기재 표시와 함께 확인된 부품·조치를 보존합니다. 미기재 분류 항목 열에서 없는 정보를 확인할 수 있습니다. 작업자가 원문에 없는 정보를 추측해 입력할 필요가 없습니다. 부분분류에서 조치 내역만 고쳐도 분류를 재확정하지 않고 저장할 수 있습니다. 전체 기록과 Excel·PDF에서 부분분류를 따로 확인합니다. 시간·일자 등에 별도 문제가 있으면 부분분류도 검토 목록에 포함될 수 있습니다.

## 검토필요란?
검토 상태와 확인된 정보는 구분합니다. 후보들이 공통으로 뒷받침하는 항목은 보존하며, 서로 충돌하거나 의심된 부품·현상은 미확정으로 둡니다. 예를 들어 '컨베어 모터 또는 센서 고장 의심'은 상세설비 컨베어만 보존하고 실제 고장 부품은 검토합니다.
원문에 '필러 반복적 문제 발생으로 조치 완료'라고 적혔다면 필러·충진기 / 세부 부품 미기재 / 고장·이상으로 부분분류합니다. 분야와 구체적인 원인·조치는 추정하지 않습니다. 원문이 잘려 복원된 한 음절만으로 새 설비 본체 고장을 자동 확정하지 않습니다.
[상세분석 → 상세설비별]과 Excel 별첨. 상세설비별분석 선택 필터은 확인된 상세설비를 라인별로 집계합니다. 부품이 없거나 검토 중이어도 확인된 상세설비에는 기록을 포함하고, 미확인 설비는 미상으로 표시합니다. 각 이력·정지시간은 한 번만 집계합니다. 이 표의 '분류 검토 중' 건수와 실제 부품별 확정 고장 건수를 구분하세요.
사람이 한 번 확인해야 하는 기록입니다. 집계에서 빠지지 않고 건수와 정지시간에 그대로 들어갑니다.
규칙에 맞지 않거나 자동 대표 선택의 보호 조건에 해당하는 기록, 정지시간·일자에 문제가 있는 기록이 해당합니다. '고장대상 설비' 기준 집계에서는 고장대상 미기재도 포함합니다.
부품명과 고장·조치 조건이 모두 맞아야 자동 후보가 됩니다. 증상·약어·브랜드명만으로 부품 종류를 추정하지 않으므로 기존 체계와 검토 건수가 달라질 수 있습니다.

## 빠르게 시작하기
1. START.bat을 더블클릭합니다.
2. MES에서 받은 Excel 파일을 프로그램 창에 끌어다 놓습니다.
3. [표준화 + 분석 실행]을 누릅니다.
4. [검토필요] 탭에서 원문과 분류를 확인하고 표의 셀을 직접 고칩니다.
5. [기준정보 · 설정 → 검토필요 색상 설정]에서 필요한 사유별 색상을 지정합니다.
6. [Excel + PDF 생성]을 누르면 분석 엑셀, PDF, 원본 검토표시 사본이 output 폴더에 저장됩니다.

# 1. 설치

## 어떤 파일을 실행하나요?
상황 | 실행할 파일
Python이 있는 PC | ZIP 압축을 모두 푼 뒤 START.bat 더블클릭
Python이 없는 PC에 줄 EXE 만들기 | Python이 있는 Windows PC에서 BUILD_EXE.bat 실행

프로그램의 원본은 Python 소스이며, EXE는 이 소스로 만듭니다. EXE 파일 이름에는 버전이 붙습니다. 버전이 없는 EquipmentFailureAnalyzer.exe는 이전 빌드이므로 쓰지 마세요.

## Python이 있는 PC
### 1단계: 압축 풀기
배포 ZIP 파일을 바탕화면처럼 파일을 저장할 수 있는 곳에 옮기고 압축을 모두 풉니다. ZIP 안에서 바로 실행하지 마세요.
START.bat, BUILD_EXE.bat, USER_GUIDE.pdf와 core·gui·report·config·scripts 폴더가 한 폴더 안에 있어야 합니다.
### 2단계: START.bat 실행
START.bat을 더블클릭합니다. 처음 실행할 때는 설치된 Python을 확인하고, 프로젝트 폴더의 .venv에 전용 실행 환경과 필요한 라이브러리를 설치합니다. 설치가 끝나면 프로그램 창이 열립니다.
지원 환경은 Python 3.11~3.13, 64비트 Windows입니다. 버전이 다르거나 32비트라면 사내 IT 부서에 지원 버전 설치를 요청하세요.
### 3단계: 다음 실행부터
다음부터도 START.bat만 실행하면 됩니다. 설치가 끝나면 인터넷이나 외부 서버 없이도 분석하고 보고서를 만들 수 있습니다.
### 인터넷이 막혀 있다면
처음 설치할 때는 승인된 패키지 저장소에 접속할 수 있거나, 미리 준비한 wheels 묶음이 있어야 합니다. 5장의 '인터넷 없이 설치'를 참고하세요.

## Python이 없는 PC
Python이 없는 PC에 START.bat만 복사하면 실행되지 않습니다. 먼저 Python이 있는 Windows PC에서 EXE를 만들어야 합니다.
### 1단계: Python이 있는 PC에서 확인
START.bat으로 v1.21.0이 열리는지 확인합니다. 분석할 파일로 Excel과 PDF가 모두 만들어지는지 확인한 다음 프로그램을 닫습니다.
### 2단계: BUILD_EXE.bat 실행
BUILD_EXE.bat을 더블클릭합니다. 빌드용 패키지를 설치하고 자동 테스트를 거친 뒤 EXE를 만듭니다. DONE 메시지와 새로 만들어진 파일을 확인하세요.
만들어진 EXE는 START.bat과 같은 폴더에 EquipmentFailureAnalyzer_v(버전).exe라는 이름으로 저장됩니다. 중간에 실패했다면 폴더에 남은 예전 EXE를 최신 버전으로 여기지 마세요.
### 3단계: 복사와 실행
만든 EXE를 이 PC에서 먼저 실행해 본 뒤, 승인된 방법으로 대상 PC에 복사합니다. 대상 PC에서는 EquipmentFailureAnalyzer_v1.21.0.exe를 더블클릭합니다. 바로 가기도 새 EXE를 가리키도록 확인하세요. 이전 EXE를 보관하더라도 전환된 규칙을 읽는 데 사용하지 않습니다.
대상 PC에는 프로젝트 폴더나 .venv를 복사하지 않습니다. 기존 설비명과 분류 설정이 필요하면 따로 옮깁니다(5장 참고).
보안 프로그램이 실행을 막으면 보안 설정을 끄지 말고 IT 승인 절차를 따르세요.

# 2. 사용 방법

## 화면 탭과 이동
화면 하단의 결과 영역은 일곱 개 탭으로 구성합니다. 분석 결과를 먼저 보고, 검토할 기록을 고친 뒤 보고서를 생성하는 순서로 사용합니다.
탭 | 내용
종합현황 | 전체 기록 건수·정지시간과 주요 분석 결과
검토필요 | 확인할 기록과 원문을 함께 보면서 분류·시간·일자를 직접 수정
상세분석 | 설비별·라인별·상세설비별·유형별 분석, 전체 기록, 교차분석, 원본 확인
설비별 유형순위 | 설비마다 빈번하거나 정지시간이 큰 고장 유형
부품별 포함 건수 | 최종 단일 부품별 고장기록 수(미확정 후보 제외)
월별 부품 추이 | 월별 최종 단일 부품의 고장기록 수와 전체 고장 대비 비율
그래프 | 설비·라인·유형과 기간별 추이를 시각적으로 비교
[상세분석] 안의 하위 메뉴에서 원하는 표를 선택합니다. [전체 기록 · 수정]에서는 검토필요가 아닌 기록도 수정할 수 있습니다. 원본과 집계표는 확인용입니다.
설비명 변환 설정·분류기준 관리·설정 폴더는 상단 [기준정보 · 설정] 메뉴에서 엽니다.
상단 [파일 · 분석 조건]을 누르면 파일·시트·분석 조건을 펼치거나 접습니다. 파일을 불러오면 펼쳐지고 분석이 끝나면 자동으로 접혀 표 영역을 넓힙니다. 접힌 상태에서도 파일명·건수·설비 분석 기준 요약을 확인할 수 있습니다.

## 1단계: 입력 파일 등록과 설비명 설정
Excel 파일을 프로그램 창에 끌어다 놓거나 [파일 찾아보기]로 고릅니다. 파일을 불러오면 등록 영역이 작아져 분석표를 넓게 볼 수 있습니다. 파일을 바꾸려면 [다른 파일 선택]을 누릅니다. [기준정보 · 설정 → 설비명 변환 설정]의 [보고서 명명 기준]에서 기본값인 [라인 코드 기준(C열)]을 선택하고 라인마다 보고서에 쓸 설비명을 입력합니다. 기존 [설비 코드 기준(E열)] 이름은 별도로 보존하며 이 기준을 선택하면 다시 사용할 수 있습니다.
설비명은 입력을 잠시 멈추거나 창을 닫으면 마지막 값으로 자동 저장됩니다. 이름을 넣지 않은 코드는 보고서에 코드 그대로 나옵니다.
파일의 열 위치가 다른 경우 [컬럼 매핑]의 라인 코드 항목을 확인합니다. 라인 코드·라인명 열 자체가 없는 파일은 기존 설비 코드 기준을 사용하며, 라인 기준의 개별 빈 코드를 다른 설비코드로 대체하지 않습니다.

## 설비군 기준 설정
같은 창의 [설비군 규칙]에서 [구분자 앞 이름], 구분자 #를 선택하면 A#1(1호기)와 A#2를 A로 묶습니다. 구분자를 - 등으로 바꿀 수 있고, [보고서 설비명 그대로]를 선택하면 자동으로 호기를 합치지 않습니다. 표의 [설비군 · 미리보기 / 개별 지정] 열에서 자동 분류를 확인하고 원하는 설비군을 직접 입력할 수 있습니다. 개별 지정값을 비우면 자동 규칙을 다시 적용합니다.
상단 [설비 분석 기준 → 설비군(이름 기준)]을 선택하고 분석하거나 파일을 생성하면 설비군별 건수·정지시간을 집계합니다. [사용자 지정 설비명]은 라인별로 변환한 호기 이름을 그대로 사용합니다. 설비군 집계에서도 원본 기록당 건수와 시간은 한 번만 반영합니다. 원본 설비코드·라인코드·기록 ID와 수동 보정 연결은 유지됩니다.

## 공장·팀 필터
상단 [파일 · 분석 조건]의 [공장 필터 / 팀 필터]에서 분석할 대상을 선택합니다. 기본은 [전체 공장 / 전체 팀]이며, 공장을 고르면 그 공장에 해당하는 팀을 보여줍니다. 공장과 팀을 함께 선택하면 두 조건에 모두 맞는 기록만 분석합니다. 미기재 항목도 선택할 수 있고 기존 분석 범위·기간·중복 제외 조건도 함께 적용합니다.
필터는 화면 집계, Excel·PDF와 원본 사본의 검토표시에 동일하게 적용합니다. 원본 사본의 행을 삭제하지 않고 선택 범위에 속하는 검토필요 행만 색칠합니다. [설비 분석 기준]은 어떤 단위로 묶을지 정하고, 공장·팀 필터는 어떤 기록을 분석할지 정합니다.
설비명·공장·팀 설정이나 컬럼 매핑을 변경하면 목록도 갱신합니다. 기존 선택값이 사라지면 '(현재 자료 없음)'으로 남겨 분석 범위가 자동으로 넓어지지 않도록 합니다. 필요한 새 값을 선택하거나 [전체 공장 / 전체 팀]으로 바꾸세요. 다른 파일이나 시트를 읽거나 초기화하면 전체 선택으로 돌아갑니다.

## 공장·팀 설정
공장·팀은 [설비명 변환 설정] 표의 오른쪽 두 열에서 지정합니다. 공장 칸에 직접 입력값이 없으면 원본 라인명의 [공장명]을 자동값으로 표시합니다. 예를 들어 '[안산] 포장라인 1'은 안산 공장으로 읽습니다. [ ]가 없으면 공장명을 직접 입력할 수 있습니다. 공장 칸을 비우면 원본 자동값으로 돌아가며, 팀 칸을 비우면 팀 미기재로 표시합니다. 공장 자동값은 직접 지정값으로 저장하지 않으므로 다른 원본 파일의 공장명도 반영됩니다.
공장·팀 직접 지정은 현재 선택한 라인 코드 또는 설비 코드 기준별로 별도 저장됩니다. 이름을 지정하지 않은 코드에도 공장·팀만 입력할 수 있습니다. 변경값은 자동저장되며 창을 닫기 전 마지막 입력도 유지됩니다. [설비 분석 기준 → 공장]은 공장별로, [팀]은 공장명과 팀명을 함께 묶어 집계합니다. 같은 팀명이 다른 공장에 있어도 합쳐지지 않습니다. Excel의 별첨. 기준정보·별첨. 고장이력·별첨. 검토품질과 PDF에 공장·팀 정보를 반영합니다.

## 2단계: 컬럼 매핑 (필요할 때만)
컬럼 매핑은 작업일자, 설비, 비고 같은 항목을 Excel의 어느 열에서 읽을지 정하는 일입니다. MES에서 내려받은 파일이면 프로그램이 제목 행과 열을 자동으로 찾습니다. 자동으로 맞춘 결과가 틀리면 [컬럼 매핑]에서 고칩니다.
고친 매핑은 제목 행이 같은 파일에 다음부터 자동으로 적용됩니다. 매핑을 바꾸면 이미 저장한 수동 보정도 새 매핑에 맞게 옮겨집니다.

## 분류 기준 확인
[기준정보 · 설정 → 분류기준 관리]에서 부품어, 증상어, 제외어와 분류 유형을 확인합니다. 운영 카탈로그의 유형 목록과 기본 규칙을 함께 사용합니다. 규칙을 고친 뒤에는 재분석하고 보고서를 다시 생성하세요. 이전 점수 설정값은 현재 판정에 사용하지 않습니다.

## 3단계: 보고서 설정 (선택)
[보고서 설정]에서 PDF의 제목, 부서, 작성자, 추가 의견을 입력하고 [저장]을 누릅니다. 비워 둔 항목은 보고서에 넣지 않으며, 제목을 비우면 기본 제목을 씁니다.
작성부서는 Excel 별첨 시트의 3행 작성정보에도 사용합니다. 부서를 비워 두면 별첨에는 확인 필요로 표시합니다. 첫 네 시트는 첨부 양식의 기존 제목·기간 배치를 유지합니다.
[비교·추이 고장사례]에서 특정 사례를 선택하면 PDF의 조직 간 사례 비교와 월간 추이가 그 사례를 표시합니다. 기본값은 발생 건수·정지시간 주요 사례 자동선정입니다. [개별 이력 부록]을 켜면 PDF 끝에 개별 분류 이력 전체를 추가합니다. 기본은 Excel 별첨. 고장이력·별첨. 부품증상상세에서 전체 이력을 확인합니다.

## 4단계: [Excel + PDF 생성]
불러온 시트와 제목 행, 분석 범위(고장만/전체 비가동), 설비 분석 기준, 기간을 확인하고 [Excel + PDF 생성]을 누릅니다. 검토필요·미확정 분류가 남아 있어도 출력됩니다. Excel 파일 이름과 저장 위치를 정하면 PDF와 원본 검토표시 사본도 같은 폴더에 만들어집니다.
저장 창은 START.bat(또는 EXE)이 있는 폴더의 output 폴더에서 열리며, 다른 폴더를 골라도 됩니다. 프로그램 폴더에 저장할 권한이 없으면 %LOCALAPPDATA%\EquipmentFailureAnalyzer\output 폴더를 기본 위치로 씁니다.
입력한 이름 | 만들어지는 파일
분석결과.xlsm | 분석결과.xlsm, 분석결과_최종보고서.pdf, 분석결과_원본_검토표시.xlsx
원본이 .xlsm이면 검토표시 사본도 .xlsm으로 저장됩니다.
작업이 끝나면 [Excel 열기], [PDF 열기], [원본 검토표시 열기], [결과 폴더]로 바로 열 수 있습니다. 세 파일은 최신 설정으로 다시 분석한 같은 기록을 기준으로 만들어집니다.

## 검토필요 색상 설정과 원본 검토표시
[기준정보 · 설정 → 검토필요 색상 설정]에서 복수검토, 규칙 미일치, 비가동코드 미기입, 기타 순서로 표시된 네 유형의 셀 배경색을 고릅니다. 기타에는 정지시간·일자·고장대상 이상 등 나머지 품질 검토 사유가 포함되며, 기존 검토 판정 기준은 유지됩니다. [기본 색상 복원] 후 [저장]으로 기본값을 적용할 수 있으며, [취소]는 저장하지 않습니다. 색상은 다음 실행에도 유지됩니다.
원본 검토표시 사본은 현재 분석 범위의 [검토필요] 원본 행 A:X 전체를 한 가지 대표 배경색으로 표시합니다. 한 행에 여러 사유가 있으면 복수검토 → 규칙 미일치 → 비가동코드 미기입 → 기타 순서에서 가장 앞선 유형의 색상을 적용합니다. 행마다 메모 하나에 모든 검토 사유를 남기므로 행의 메모에서 상세 사유를 확인할 수 있습니다. 기존 메모는 보존하며, 입력 원본의 값이나 기존 시트 구조는 변경하지 않고 별도 사본을 만듭니다.

## 결과 파일 구성
Excel 파일의 기본 구성은 11개 표시 시트이며, 제품 자료가 있으면 별첨. 제품교차분석을 추가합니다. 숨김 시트는 선택 조건의 계산에 사용합니다.
시트 | 내용과 관리자 활용

별첨. 기준정보의 부품 식별 규칙은 긴 조건식의 자동 줄바꿈을 끄고 표시하므로, 전체 내용은 해당 셀을 선택한 뒤 Excel 수식 입력줄에서 확인합니다.
통합 구조는 이후 생성하는 보고서부터 적용하며 입력 원본과 이미 저장한 보고서는 자동 변경하지 않습니다. 기존 시트별 통합 근거는 docs\REPORT_SHEET_REVIEW.md에 있습니다.
PDF는 핵심 요약과 범위, 찾아보기, 건수·정지시간 순위, 공장·팀별 주요 이슈, 동일 설비·사례 비교, 사례별 월간 변화, 전체 월별 추이, 관리 검토사항, 설비·부품 부록 순서입니다. 책갈피로 구역·설비에 바로 이동합니다. 개별 분류 이력 전체는 설정에서 켠 경우에만 마지막 부록에 추가합니다.
기본 결과는 검색형 .xlsm입니다. 매크로를 허용하고 공장·팀·라인·상세설비·세부부품·기준 조직 필터 셀을 선택하면 검색창이 열립니다. 같은 셀에서 다시 검색하려면 더블클릭합니다. 입력창 아래 후보는 정확 일치, 앞부분 일치, 포함 일치, 오타 유사도 순입니다. 공백·구분자는 검색 비교에서 무시합니다.
후보를 클릭하거나 ↑↓ 후 Enter로 하나를 확정하면 표와 Excel 차트가 갱신됩니다. 입력만으로 집계하지 않으며 Esc·취소·후보 없음은 기존 선택을 유지합니다. (전체)로 조건을 해제합니다. 비교 방식·분석 기준은 기본 목록에서 선택합니다.
저장 창에서 일반 .xlsx도 선택할 수 있습니다. .xlsx 또는 매크로 미허용 상태에서는 기본 드롭다운으로 항목을 선택합니다. 완성된 보고서 사용에는 개발용 'VBA 프로젝트 개체 모델에 안전하게 액세스'가 필요하지 않습니다. 입력 원본의 매크로는 분석기가 실행하지 않으며 검색 코드는 새 결과 보고서에만 포함합니다.
01~04의 최하위 집계는 세부부품입니다. 서로 다른 고장 현상도 상세설비·부품이 같으면 합산하며 미기재 항목은 미기재로 남깁니다. 고장 현상·조치·판정 근거는 이력과 검토 자료에서 확인합니다. 사내 MES에서 설비명으로 부르는 전체 생산설비 묶음을 이 보고서에서는 라인으로 표시하고, 필러·컨베어 등 개별 모듈은 상세설비로 구별합니다. PDF의 고장사례 선택은 별도 기능입니다.
유형별·부품별·원본데이터 시트는 출력하지 않습니다. 원본 대조에는 함께 생성한 원본_검토표시 사본을 사용합니다. 분석 데이터와 원본 파일은 삭제하지 않습니다. 출력 범위의 기록만 조회하며 가동시간·생산량을 보정한 고장률 비교는 아닙니다.
월별 0건은 해당 사례의 기록이 없다는 뜻입니다. 기록은 있으나 정지시간이 모두 비어 있으면 시간은 빈칸으로 남깁니다. 날짜 미상은 추이에서 제외하고, 첫·마지막 월의 부분기간 가능성이 있으면 전월·전년동월 증감을 비워 오해를 줄입니다.

## Excel 양식과 초기 필터
첫 네 시트는 첨부한 사용자 양식을 고정 템플릿으로 사용합니다. 최신 지시에 따라 공통 작성 Rule보다 첨부 양식을 우선하며 글꼴·제목·빈행·차트 디자인·인쇄 설정을 유지합니다. 이 시트들에 B2 제목·A열 여백·표 행 22pt를 새로 덧씌우지 않습니다. 분류 규칙과 PDF의 내용 구성은 그대로입니다.
사용자가 추가로 지정한 두 치수는 통일합니다. 첫 네 시트의 A:L 열 너비는 13, 본문·표·필터 행 높이는 27.95pt입니다. 제목·빈행의 기존 높이는 유지하며 글자 넘침을 막는 병합을 보완합니다.
01.종합현황 A5는 기록 건수·정지시간 합계·평균 정지시간, A6은 분류 상태, A35는 우선 확인할 라인을 표시합니다. 수식으로 계산하고 평균의 분모는 시간이 기재된 기록 수입니다. 시간 미기재를 0분으로 바꾸지 않습니다. 라인 차트는 [남양주]ARCIL #1처럼 설비명 변환값의 공장 접두어를 보존합니다.
별첨 시트에는 제목 B2·본문 B6·A열 여백과 공통 작성 기준을 적용합니다. KoPubWorld돋움체 Medium의 제목 16pt·구역 제목 14pt·표와 설명 11pt, 표 행 22pt를 사용합니다. 작성일·작성부서는 제목 끝 열 3행에 오른쪽 정렬하고, 부서 미상은 확인 필요로 표시합니다.
조회 필터는 전체 또는 목록 첫 항목으로 시작합니다. 공장·팀·라인·상세설비·세부부품은 전체, 기준 조직·비교 방식·분석 기준은 첫 항목으로 시작합니다. 저장한 편집 설정은 유지합니다. 빨강·파랑 증감 표시는 기준 조직·전월·전년동월 대비 비교 수치에만 적용하며 일반 건수·시간·비중은 중립색입니다. 고장이력 증가·시간 증가는 빨강, 감소는 파랑입니다.
Excel에서 최종 파일을 저장·닫기·재열기한 뒤 별첨 시트의 A열 실제 표시 너비가 1인지 확인하는 검증은 확인 필요입니다. 생성 라이브러리나 XLSX 내부의 너비값만으로 이 검증을 완료 처리하지 않습니다. 첫 네 시트의 A열은 승인된 너비 13을 사용합니다.

## 관리 업무별 권장 열람 순서
1. 보고 전: 별첨. 검토품질에서 검토 기록을, 별첨. 기준정보에서 기간·공장·팀·누락·분류 집계를 확인하고, 프로그램의 [검토필요]에서 보정한 뒤 보고서를 다시 만듭니다.
2. 정비 우선순위 회의: 01.종합현황 → 02.주요이슈_팀별 → 별첨. 라인별분석·상세설비별분석에서 건수 또는 정지시간을 선택합니다.
3. 예방정비·예비품 검토: 04.고장추이에서 세부부품의 변화를 확인합니다. 이력 건수는 교환 부품 수나 재고 소요량과 구별합니다.
4. 개별 고장 점검: 별첨. 고장이력의 표준화 후 내용과 별첨. 부품증상상세를 확인합니다. 기록 ID·원본 행으로 원본 검토표시 사본과 대조합니다.
5. 집계 기준 확인: 별첨. 기준정보에서 설비명·공장·팀과 분류 규칙을 확인합니다. 제품 자료가 있으면 별첨. 제품교차분석으로 제품 조건별 기록을 비교합니다.

## 보고서 읽는 기준
선택형 별첨의 100%는 현재 공장·팀·라인·상세설비 조건에 해당하는 전체 기록 또는 정지시간입니다. 분석 기준으로 상위 10개를 정렬하고 나머지는 기타로 합산하여 전체 합계를 보존합니다. 미기재 부품도 별도 항목으로 포함하며 의심 후보는 확정 부품으로 합산하지 않습니다.
별첨의 분석 기준을 건수에서 정지시간으로 바꾸면 표의 순위와 아래 구성비 차트가 함께 바뀝니다. 정지시간이 전부 미기재인 항목은 시간 순위에서 제외합니다. 기간별 추이는 달력순입니다.
제품별 건수·시간은 관찰된 기록의 비교입니다. 생산량·가동시간 없이 제품 고장률이나 위험 차이를 판단하지 않습니다.

# 3. 검토필요 처리

## 어떤 기록이 검토필요가 되나요?
사유 | 뜻
비가동코드 미기입 | 비가동코드(중·소)가 비어 있고 비고에서 부품과 증상을 찾지 못함. 원본 입력을 확인하고 표에서 분류를 정하거나 분류 규칙을 보완
규칙 미일치 | 비가동코드는 입력됐지만 비고에서 부품과 증상을 찾지 못함. 분류 규칙을 보완하거나 표에서 분류를 정함
후보 충돌 | 같은 명사에 동률의 상충 규칙이 맞거나 고장 대상이 불명확한 공동주어가 있음
대안 유형 | 또는·혹은 등 서로 대안으로 적힌 유형. 실제 동시 고장과 구분하여 확인 필요
자동 대표 선택 제외 | 의심·대안, 미등록 다른 물리 고장, 불명확한 공동주어, 동률 상충 규칙, 부품명만 있는 기록
정지시간·일자 문제 | 정지시간이 없거나 형식이 틀림, 작업일자가 없음, 종료 시각이 시작 시각보다 이름, 입력한 정지시간과 시작·종료 차이가 2분 넘게 다름
고장대상 미기재 | 설비 분석 기준이 '고장대상 설비'일 때만 검토필요. 다른 기준에서는 참고 정보로만 표시
검토필요도 전체 건수·정지시간에는 포함합니다. 최종 분류는 비워 두고 후보는 부품 건수에 합산하지 않습니다. 후보 근거와 원문을 확인해 하나의 분류를 확정하세요.

## 표에서 직접 수정
[검토필요]나 [상세분석 → 전체 기록 · 수정]의 표에서 수정할 셀을 더블클릭하거나 F2를 누릅니다. 편집 가능한 셀은 파란색이고 분류 열에는 목록을 펼치는 화살표가 있습니다. 검토 표는 대분류·상세설비·세부 부품·소분류를 앞에 표시하고, 원본 설비·원본 중·소분류·고장내용을 묶어서 보여 줍니다. 분류 상태와 검토 사유, 분류 근거·후보를 원문과 대조하세요.

[검토필요] 표의 좌상단 빈 칸을 클릭하면 표시된 열과 현재 검색 결과의 모든 행을 제목 포함으로 클립보드에 복사합니다. 화면 정렬 순서를 유지하며, 추가 열 표시를 켜면 그 열도 함께 복사합니다. 숨긴 내부 ID 열은 제외합니다. 최종 분류 한 건 선택창은 부모 창 중앙에 뜨며 제목 표시줄로 이동하고 모서리로 크기를 조절할 수 있습니다. 취소·Esc·닫기는 저장하지 않습니다.
항목 | 수정 방법 | 저장 시점
대분류·상세설비·세부 부품·소분류 | 그리드 셀에서 연속 선택, 다음 셀·다음 행으로 자동 이동 | 메모리 반영, 표준화 버튼에서 일괄 저장
추천 후보 | 후보 비교창에서 더블클릭 또는 Enter로 하나 선택 | 메모리 반영, 표준화 버튼에서 일괄 저장
작업일자·정지시간·고장대상·제품 | 수정할 셀에 값 입력 | Enter 또는 다른 셀로 이동
원본 정보·분석 집계 | 읽기 전용 | 수정하지 않음
고장 분야·상세설비·세부 부품·고장 현상은 각각 독립적으로 선택합니다. 부품군은 종류 탐색에만 사용하며, 다른 축을 변경해도 기존 선택을 유지합니다. 네 항목이 완성되면 확정 대기로 표시하고 해당 행만 갱신하며, 다른 행의 미완성 선택과 커서·스크롤은 유지합니다. 분류 목록은 분석 시 캐시하고 입력 중 파일을 읽거나 쓰지 않습니다. 모든 미확정 선택은 프로그램 종료 시 사라집니다. [표준화 + 분석 실행]은 현재 파일의 대기 분류를 한 번에 검증하고 확정 파일을 한 번 저장합니다.
선택한 분류는 표준화 전까지 검토 목록에 남고 노란색으로 표시됩니다. 분류명은 자유 입력하지 않고 이력당 하나만 선택합니다. 우클릭 [임시 분류 선택 취소]는 선택만 지우고 기존 확정값과 다른 보정을 유지합니다. 입력 중에는 행이 자동 재정렬되거나 검색에서 사라지지 않으며, 제목 정렬이나 검색어를 다시 조작하면 현재 값에 맞춰 갱신합니다.
바꾼 항목만 수동 보정으로 저장됩니다. 정지시간이나 작업일자만 고치면 분류는 확정되지 않으므로, 미확정 후보 표시는 그대로 남습니다. 일반 셀의 값을 비우면 그 항목의 수동 보정을 해제하고 원본 값으로 돌아갑니다. [분류 보정 해제]는 그 기록의 분류 보정만 해제하고 다른 보정은 유지합니다.
행을 마우스 오른쪽 버튼으로 누르면 [최종 분류 한 건 선택], [임시 분류 선택 취소], [분류 보정 해제], [이 기록의 수동 보정 모두 해제]를 선택할 수 있습니다. 분류만 해제하면 그 해제도 표준화 전까지 대기하며 시간·일자·고장대상·제품의 보정은 유지합니다. 임시 선택 취소는 확정값을 바꾸지 않습니다. 모두 해제는 기존의 전체 보정 해제 동작입니다.
시간·일자 등 일반 값을 저장하면 자동 재분석하고, 분류는 표준화 버튼에서 일괄 확정한 뒤 검토 건수와 집계표를 갱신합니다. Excel과 PDF는 다시 만들어야 바뀐 확정값이 들어갑니다. 표준화 전에도 출력할 수 있지만 임시 선택은 보고서에 확정값으로 반영하지 않습니다. 정렬하거나 검색한 상태에서도 같은 원본 기록에 선택과 보정을 연결합니다.

## 분류 규칙 편집
[분류기준 관리]에서 규칙을 추가하거나 고칩니다. 각 열의 뜻은 4-4절에 있습니다.
context와 symptom에는 찾을 말을 '|'로 구분해 적습니다(예: 솔밸브|솔레노이드). 정규식 문법과 띄어쓰기 제거 규칙은 4-4절을 참고하세요. symptom의 '.'은 부품어만 있어도 맞는다는 뜻입니다.
role 칸에는 규칙 종류를 적습니다. component는 부품 규칙, fallback은 부품이 미기재된 증상에 쓰는 규칙, override는 작업자 조작처럼 원인을 바로 정하는 규칙입니다. nopart는 부품 후보가 하나도 없을 때만 적용하는 규칙(공정·자재 현상, 부품 미상 제어 오류)입니다.

- 열 맞추기: 열 이름은 띄어쓰기와 대소문자를 무시하고 비교합니다. 항목마다 받아들이는 열 이름 목록(column_mapping.json)이 있습니다.
- MES 형식 인식: '비가동 시간(분)', '비가동 코드(중)', '비가동 유형' 열이 모두 있으면 MES 비가동 목록으로 보고, 고장대상 설비 판정처럼 MES에만 맞는 처리를 적용합니다.
- 건너뛰는 행: 빈 행, 중간에 다시 나오는 제목 행, '합계'·'총계'·'소계'로 시작하는 행은 건너뜁니다. 건너뛴 행은 모두 별첨. 기준정보 시트의 데이터품질 영역에 남습니다.
- 병합된 셀: 원본에서 실제로 병합한 범위에만 값을 채웁니다. 그냥 비어 있는 칸을 위 칸 값으로 채우지 않습니다.

## 4-3 기록 정리
분류하기 전에 기록마다 다음 일곱 가지를 정리합니다.
- 고장 여부: 비가동 유형이 '고장'(코드 TR)이면 고장 기록입니다. 계획운휴(PI)와 작업운휴(WI)는 원본데이터 시트에는 남기지만, 분석 범위가 '고장만'이면 집계에서 뺍니다.
- 날짜: 2026-01-02, 20260102, 2026.01.02, 2026년 1월 2일, Excel 날짜 숫자를 모두 같은 날짜로 읽습니다.
- 정지시간: MES의 '비가동 시간(분)' 값을 먼저 씁니다. 이 값이 비어 있으면 종료 시각에서 시작 시각을 뺀 시간을 씁니다. 두 값이 2분 넘게 다르면 검토필요로 표시합니다. 자정을 넘긴 정지도 제대로 계산합니다.
- 설비명: 기본은 라인 코드(C열)를 [설비명 변환 설정]의 이름으로 표시합니다. 기존 설비 코드(E열) 기준도 선택할 수 있으며 두 변환표는 별도로 저장합니다. 이름을 정하지 않은 코드는 그대로 둡니다. 설비군은 변환된 이름의 구분자 규칙과 직접 지정값으로 정합니다.
- 고장대상 설비: MES의 '비가동 코드(중)' 값이 1P, 2P, 3P처럼 공장 구분으로 시작하면(예: 3P I/C AJ-10 제대기) 그 값을 고장대상 설비로 봅니다. 그 밖의 값이면 고장대상이 입력되지 않은 것으로 봅니다.
- 비고 정리: 영문은 소문자로 바꾸고, 겹친 띄어쓰기는 하나로 줄입니다. 같은 대상의 철자·동의어 표기를 맞춥니다(실러 → 씰러, 벨브 → 밸브, 컨베이어 → 컨베어, 솔레노이드 벨브 → 솔밸브 등). 또 MES 입력란은 끝 글자가 잘린 경우가 많아, 구절 끝에 혼자 남은 잘린 어미를 복원합니다('교' → '교체', '고' → '고장', '조' → '조정' 등). 원래 비고는 그대로 두고, 정리한 문장은 '정규화 내용' 열에 따로 저장합니다.
- 기록 ID: 기록 내용으로 기록마다 고유한 ID를 만듭니다. 사람의 지문처럼, 내용이 같으면 언제나 같은 ID가 나옵니다. 수동 보정은 이 ID에 연결해 저장하므로, 같은 자료를 다시 불러와 분석해도 보정이 그대로 적용됩니다. 내용이 완전히 같은 기록이 여러 개면 '동일 기록 후보'로 표시합니다.

## 4-4 고장 분류 원리
### 규칙의 구성
규칙 하나는 '이 부품어 뒤에 이 증상어가 나오면 이 고장 유형'이라는 뜻입니다. 부품어는 부품을 가리키는 말, 증상어는 그 부품에 생긴 일을 나타내는 말입니다. 규칙표([분류기준 관리] 또는 Excel의 별첨. 기준정보 시트 아래쪽 부품 식별 규칙 영역)의 열은 다음과 같습니다.
열 | 뜻 | 예 (근접센서 규칙)
context (부품어) | 부품을 가리키는 말 | 근접센서
symptom (증상어) | 부품에 생긴 일 | 고장, 소손, 교체, 점검 등
exclude (제외어) | 이 말이 있으면 규칙을 적용하지 않음 | 기본 근접센서 규칙에서는 빈칸. 정상·부정·예정 표현은 공통 판정에서 처리
priority (우선순위) | 같은 부품의 세부 규칙 선택과 정렬에 사용. 조건에 맞지 않는 규칙에는 적용하지 않음 | 84
role (규칙 종류) | 부품 규칙, 부위 미기재 규칙, 원인 규칙, 부품 없을 때 규칙 가운데 하나 | component
major·middle·minor | 내부 부품 식별 경로(분야·부품군·세부 부품 종류) | 전기·제어 / 센서·검출 / 근접센서
기본 규칙에는 부품 식별 규칙(component)과 부품 후보가 없을 때 쓰는 nopart 규칙이 있습니다. 실제 활성 규칙 수와 각 조건은 분류기준 관리와 별첨. 기준정보에서 확인합니다. 부위 미기재 규칙(fallback)과 원인 규칙(override)은 기본 규칙에 포함하지 않습니다. 규칙 파일 형식에서는 이 역할을 계속 지원하므로 기존 사용자 규칙의 내용은 별도로 보존합니다.
원문에 부품명이 없이 '파손', '트러블' 같은 증상만 있으면 세부 부품을 추정하지 않고 규칙 미일치(비가동코드가 비어 있으면 비가동코드 미기입)로 남깁니다. 부품군은 명확하지만 종류가 없을 때만 그 부품군의 종류 미상 항목을 사용합니다. TC 단독 표기나 WAGO 번호만으로 센서 방식·제어 모듈 종류를 단정하지 않습니다. 부품 언급 없이 WAGO 에러 번호나 통신 이상만 적힌 기록은 종류를 추정하지 않는 제어기(종류 미상)으로 분류합니다. 고장내용에 부품명이 없으면 비가동코드(소)에 적힌 부품명을 사용합니다.

### 1단계: 구절로 나누기
비고를 줄바꿈, 빗금(/), 괄호, 문장 끝 마침표, ' - ', 화살표가 있는 곳에서 나눕니다. 나눈 구절 안에서는 띄어쓰기를 지우므로 '센서 교체'와 '센서교체'를 같은 말로 봅니다. '1.3.5번'처럼 숫자 사이에 찍힌 점에서는 나누지 않습니다.

### 2단계: 부품과 증상 짝짓기
부품어를 찾으면 그 뒤에서 증상어를 찾습니다. 찾는 범위는 15자 이내이고, 다음 부품어가 나오면 거기서 멈춥니다.
예를 들어 '제함기 푸셔 실린더 센서 교체'에서 푸셔의 증상 찾기는 실린더 앞에서, 실린더의 증상 찾기는 센서 앞에서 멈춥니다. 뒤에 '교체'가 붙은 부품은 센서뿐이므로 센서를 부품 후보로, 교체를 별도 조치로 식별합니다. 명시된 고장 현상이 없으므로 현상 미기재로 부분분류하고 확인된 부품과 조치를 보존합니다.
이 밖에도 다음 기준을 따릅니다.
- 부정하는 말은 증상으로 보지 않습니다. '센서 이상 없음, 모터 트립'은 센서가 아니라 모터로 분류합니다.
- 장소를 나타내는 말은 고장 부품으로 보지 않습니다. '트레이 체인 메인, 보조 스프라켓에서 이탈'에서 스프라켓은 체인이 빠진 위치이므로 체인으로 분류합니다.
- '및', '와/과', 쉼표로 이어 쓴 부품은 뒤에 오는 증상을 함께 받습니다.
- 부품어가 없는 구절은 새 주어나 새 설비가 없고 조치 설명이 이어질 때만 바로 앞 부품에 연결합니다. '로드리스 실린더 파손/교체'에서 '교체'는 실린더에 붙지만, 새 대상이 나타나면 앞 부품의 설명으로 합치지 않습니다.
- 부품 이름 속에 든 말은 증상으로 보지 않습니다. '고정볼트'의 '고정'은 조치가 아니라 부품 이름의 일부입니다.

### 3단계: 증상어의 세 종류
증상어는 부품이 실제로 고장 났다는 근거가 얼마나 확실한지에 따라 세 종류로 나눕니다.
종류 | 예 | 분류에서 쓰는 정보
교체·수리 | 교체, 교환, 수리, 정비, 가공, A급, 신규 | 완료 여부를 확인해 조치 대상 부품을 식별. 고장 현상과 원인은 별도 확인
고장 증상 | 고장, 파손, 에러, 작동불량, 마모, 이탈, 누수 등 | 명확한 단일 부품 고장은 후속 조치보다 먼저 선택
조정·점검 | 조정, 점검, 청소, 위치, 타이밍 등 | 완료 조치는 대상 식별에 사용. 위치·타이밍 등 명사만으로 완료 작업을 추정하지 않음

### 4단계: 결정 규칙으로 후보 해소
일치한 후보를 고장 유형별로 모읍니다. 같은 유형을 지지하는 규칙이 여럿이거나 같은 표현이 반복되어도 서로 다른 고장으로 세지 않습니다. 원인 규칙, 부품 규칙과 부위 미기재 규칙의 관계, 복합 부품명의 구체성, 고장·교체 근거, 명시적인 인과관계와 MES 부위 단서를 사용해 후보를 해소합니다.
예를 들어 구체적인 부품 규칙이 같은 고장 근거를 설명하면 부위 미기재 규칙보다 우선할 수 있습니다. 동일한 부품에 맞은 세부 규칙이나 부위 미기재 후보끼리는 규칙의 우선순위를 사용합니다. 고장과 교체가 적힌 부품은 점검만 한 부품과 구분합니다. 이러한 결정 규칙으로 명확한 고장을 먼저 선택한 뒤, 남은 후보에는 대표 자동선택 기준을 적용합니다.
직접 명시된 고장이 한 부품에만 있고 다른 부품은 완료된 조치 대상으로만 나타나면 명시된 고장 부품을 먼저 선택합니다. 그 뒤에도 복수 부품·현상·다른 설비의 후보가 남으면 원문 고장 또는 완료 조치 근거가 있는 1순위를 이력 대표로 자동 선택하고 판정 사유에 1순위 대표 자동선택을 표시합니다.
의심·또는·대안, 미등록 대상의 다른 물리 고장, 고장 대상이 불명확한 공동주어, 같은 명사의 동률 상충 규칙, 부품명만 있는 기록은 자동 대표 선택에서 제외합니다. 순위는 정확도나 확률이 아니며, 대표를 하나 골라도 원문과 모든 후보를 보존하고 다른 실제 고장이 없다고 해석하지 않습니다.

### 5단계: 자동분류와 검토필요
판정 | 조건
규칙분류 | 대표 분류가 정해지고 고장 분야·상세설비·세부 부품·고장 현상의 네 항목이 모두 확인됨
부분분류 | 대표 분류의 네 분류축 중 일부가 미기재. 확인된 항목을 보존하고 미기재 항목 표시
1순위 대표 자동선택 | 복수 부품·현상·설비 중 원문 고장 또는 완료 조치 근거가 있는 1순위를 대표로 선택. 상태는 규칙분류 또는 부분분류
대안 유형 검토 | 또는·혹은 등 서로 대안으로 적힌 후보가 있음
대표 선택 제외 검토 | 의심·미등록 다른 물리 고장·불명확한 공동주어·같은 명사 동률 상충·부품명만 있는 기록
규칙 미일치 | 후보가 전혀 없음(비가동코드는 입력됨)
비가동코드 미기입 | 후보가 전혀 없고 비가동코드(중·소)도 비어 있음
사용자확정은 자동 판정보다 우선합니다. 시간만 수정하면 자동 분류 상태와 후보 검토는 유지됩니다. 이전 점수 설정값으로 현재 판정을 조정하지 않습니다.
상세·검토 표와 Excel에는 분류 판정 사유(classification_reason)와 후보별 규칙·근거(candidate_evidence)를 표시합니다. 원문, 일치 규칙, 부품·증상 근거와 판정 사유를 함께 확인하세요.
검토필요도 전체 건수·정지시간에 포함합니다. 후보는 실제 부품 고장으로 합산하지 않고 최종 분류를 비워 둡니다. 사람이 하나를 확정하면 유형별·부품별 집계를 갱신합니다. 시간·날짜·고장대상 문제는 분류 확정과 별도로 검토합니다.

### 최종 분류와 부품별 추이
상세 표에는 최종 분류와 분류 판정 사유, 순위·근거가 있는 후보 목록을 표시합니다. 과거 수동 복수 분류는 후보로만 보존하고 사용자가 하나를 재확정합니다. 새 자동 분석에서는 보호 조건에 해당하지 않는 근거 있는 1순위 후보를 대표로 선택합니다.
원본 1행을 한 기록으로 유지합니다. 부품별 건수에는 대표로 선택한 실제 부품만 한 번 포함하며, 한 기록에 언급된 모든 고장 부품의 총수는 아닙니다. 월별 부품 추이는 유효한 날짜의 최종 단일 부품을 집계하고 해당 월의 모든 고장이력을 비율 분모로 사용합니다. 미확정 후보는 분모에만 포함하며 기록이 전혀 없는 월의 비율은 빈칸입니다.

### 분류가 하지 않는 일
- 고장 원인을 확정하지 않습니다. 비고에 적힌 부품과 증상을 기준으로 나눌 뿐입니다.
- 뜻을 짐작하지 않습니다. 규칙에 없는 말만 있으면 규칙 미일치(비가동코드가 비어 있으면 비가동코드 미기입)로 남깁니다.
- 수동 보정은 그 기록 하나에만 적용합니다. 비슷한 문장에 자동으로 퍼뜨리지 않습니다.

## 4-6 집계 방법
- 원본 1행을 기록 1건으로 셉니다. 이어지는 기록을 임의로 합치지 않습니다.
- 정지시간은 기록별 시간을 더한 값입니다. 여러 라인이 같은 시간에 멈춘 부분을 빼지 않으므로, 공장 전체가 실제로 멈춘 시간과는 다릅니다.
- 건수 비율은 '해당 항목 건수 ÷ 전체 건수', 시간 비율은 '해당 항목 정지시간 ÷ 전체 정지시간'입니다.
- 정지시간이 없는 기록은 건수에는 넣고, 시간 합계와 평균에서는 뺍니다. 작업일자가 없는 기록은 기간별 추이에서 뺍니다.
- 분석표는 정지시간이 큰 순서로 놓고, 정지시간이 같으면 건수가 많은 순서로 놓습니다. 설비별 유형순위는 건수가 많은 순서입니다.
- 원형 차트는 상위 5개 유형과 나머지를 합친 '기타'로 그립니다. 100%는 그 설비의 전체 기록 건수이며, 비가동코드 미기입·규칙 미일치도 들어갑니다.
- 검토필요 기록도 모든 집계에 들어갑니다.
- 가동시간이나 생산량 자료가 없으므로 고장률, MTBF(평균 고장 간격), MTTR(평균 수리 시간)은 계산하지 않습니다.
- 수식으로 연결된 Excel 집계 칸은 별첨. 고장이력 시트를 참조하며 Excel에서 다시 계산할 때 값을 갱신합니다. 부품별 표·분류 상세·검토 목록·차트 등은 생성 시점 자료입니다. 일관된 보고서를 만들려면 프로그램에서 수정한 뒤 보고서를 다시 생성하세요.
설비를 어떤 기준으로 묶을지는 화면의 [설비 분석 기준]에서 고릅니다.
기준 | 묶는 방법
사용자 지정 설비명 | 선택한 라인/설비 코드로 묶고, 정한 이름으로 표시 (기본값: 라인 코드)
설비군(이름 기준) | 변환된 설비명의 구분자 규칙과 직접 지정한 설비군으로 묶음. A#1·A#2 → A
공장 | 직접 지정한 공장명 또는 원본 라인명의 [공장명]으로 묶음
팀 | 공장·팀명으로 묶음. 다른 공장의 같은 팀명은 별도 집계
고장대상 설비 | 비가동 코드(중)의 설비로 묶음. 비어 있으면 '라인 / 고장대상 미기재'로 묶음
등록 설비 | MES 설비명 그대로 묶음

## 4-7 데이터 구조
프로그램이 다루는 개념과 개념 사이의 관계를 정리하면 다음과 같습니다.
개념 | 뜻 | 관계
원본 행 | MES Excel의 한 줄 | 기록 1건이 됨
기록 | 비가동 한 건. 날짜, 정지시간, 라인, 설비, 비고를 담음 | 비가동 유형과 기록 ID가 하나씩 있음
비가동 유형 | 고장, 계획운휴, 작업운휴 | 고장만 분류함
라인 | 생산 라인 | 여러 설비가 속함
설비 | MES에 등록된 설비(코드) | 보고서에는 정한 이름으로 표시
고장대상 설비 | 비가동 코드(중)에 적힌 설비 | 등록 설비와 다를 수 있음
고장 유형 | 고장 분야 / 상세설비 / 세부 부품 / 고장 현상 | 독립 선택, 부품군 파생·조치 별도
규칙 | 부품어 + 증상어 → 고장 유형 | 배포 기본 규칙과 보존한 사용자 규칙
분류 상태 | 규칙분류, 부분분류, 검토필요, 비가동코드 미기입, 규칙 미일치, 사용자확정, 분류대상 외 | 기록마다 하나
분류 근거 | 맞은 규칙, 일치한 말, 자동선택 사유 | '분류 근거' 열에 표시
수동 보정 | 사람이 고친 값 | 기록 ID로 연결
분류 상태별 뜻과 집계 방식은 다음과 같습니다.
상태 | 뜻 | 집계
규칙분류 | 네 분류축이 모두 확인된 완전 자동분류 | 분류된 유형으로 집계
부분분류 | 대표 분류의 일부 분류축이 원문에 미기재 | 확인된 항목을 보존하고 미기재 항목 표시. 실제 부품이 확인되면 부품 집계 포함
검토필요 | 의심·대안·미등록 다른 고장 등 자동 대표 선택 제외 조건 | 최종 분류는 빈칸, 전체 건수·시간에는 포함하고 부품 집계에서는 제외
비가동코드 미기입 | 확정할 규칙이 없고 비가동코드(중·소)가 비어 있음 | 검토 중 전체 건수·시간에는 포함하고 부품 집계에서는 제외. 최종 분류 선택 후 보고서 생성
규칙 미일치 | 비가동코드는 있으나 확정할 규칙이 없음 | 검토 중 전체 건수·시간에는 포함하고 부품 집계에서는 제외. 최종 분류 선택 후 보고서 생성
사용자확정 | 사람이 표에서 분류를 확정함 | 확정한 유형으로 집계
분류대상 외 | 고장이 아닌 비가동. 분석 범위가 '전체 비가동'일 때만 나옴 | '분류대상 외'라는 이름으로 건수와 시간을 집계
정지시간·작업일자에 문제가 있는 기록은 분류 상태와 관계없이 [검토필요] 탭에 함께 나옵니다.

## 4-8 안전장치
- 원본 Excel은 읽기만 합니다. 보고서를 원본과 같은 파일 이름으로 저장할 수 없습니다.
- 분석 보고서는 원본의 글자를 글자로 저장하며, 원본 검토표시 사본은 원본 수식을 그대로 보존합니다.
- MES의 생성·수정 사용자 열은 분석 보고서에 넣지 않습니다. 원본 검토표시 사본에는 원본 열이 그대로 남습니다.
- 설정을 저장할 때는 이전 파일을 백업합니다.
- 카탈로그 전환 전 설정을 config\backup 폴더에 백업합니다. 기존 수동 보정 파일은 바이트 그대로 보존합니다.
- schema 7을 지원하지 않는 구버전은 규칙 읽기가 차단됩니다. 새 대표 자동선택 정책은 v1.18.0 이상 실행파일로 적용합니다.

# 5. 업데이트·문제 해결

## 새 버전 설치와 기존 설정 유지
프로그램을 닫고, 새 ZIP의 압축을 새 폴더에 푼 뒤 START.bat을 실행하세요. 같은 Windows 사용자의 아래 설정 폴더를 지우지 않으면 설비명과 설정이 그대로 남습니다.
%LOCALAPPDATA%\EquipmentFailureAnalyzer\config
첫 운영 카탈로그 전환에서는 새 기본 규칙 전체를 설치하고 알려진 이전 기본 규칙을 퇴역시킵니다. 새 목록 범위 밖의 기존 사용자 규칙은 내용과 우선순위를 보존한 채 비활성화합니다. 새 목록 범위 안의 사용자 규칙은 유지합니다. 전환 전 파일은 config\backup\날짜_시각 폴더에 백업되고, 결과는 상태 표시줄에 나옵니다.
기존 manual_overrides.json은 카탈로그 전환 시 바이트 그대로 보존합니다. 이전 스키마 수동확정·과거 복수 분류는 원래 저장값을 보존한 채 검토 후보로 표시하며, 첫 항목이나 없는 증상을 임의로 최종 확정하지 않습니다. 같은 운영 카탈로그의 후속 실행에서는 직접 비활성화하거나 삭제한 새 규칙을 되살리지 않습니다. 전환 중 오류가 나면 완료로 표시하지 않고 오류를 안내하므로, 원인을 해결한 뒤 다시 실행하면 재시도할 수 있습니다.
한 PC에 설치한 모든 버전이 이 설정 폴더를 함께 씁니다. 현재 규칙은 schema 7이며 필요 버전 메타데이터는 v1.18.0입니다. 최소 실행 버전보다 이전인 EXE는 같은 schema 7을 지원해도 새 규칙 읽기가 차단됩니다. 새 대표 자동선택 정책은 최신 START.bat 또는 v1.18.0 이상 EXE로 실행하세요. schema 7 미지원 구버전은 규칙 읽기가 차단됩니다. 과거 v1.10.0의 schema 4는 이전 변경 이력입니다.
버전별로 달라진 점은 docs\CHANGELOG.md에 정리되어 있습니다.

## 다른 PC로 설정 옮기기
양쪽 PC에서 프로그램을 닫고 config 폴더를 백업한 뒤 옮기세요. 자동으로 동기화되지 않습니다.
파일 | 내용
equipment_names.json | 라인·설비 코드 변환표, 선택 기준, 설비군 규칙, 공장·팀 직접 지정값
manual_overrides.json | 수동 보정
column_overrides.json | 컬럼 매핑
classification_config.xlsx | 분류 규칙
classification_catalog.json | 운영 분류 계층과 카탈로그 버전
final_report.json | PDF 설정

## 인터넷 없이 설치
Windows와 Python의 버전·비트가 같은 PC에서 scripts\prepare_wheels.bat을 실행해 필요한 파일을 모읍니다. 만들어진 wheels 폴더 전체를 대상 PC의 프로젝트 폴더 안 wheels 폴더로 옮긴 뒤 START.bat을 실행합니다. 일부 패키지만 있으면 설치에 실패합니다.
