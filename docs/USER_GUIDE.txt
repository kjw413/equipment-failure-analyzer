
# 설비 고장 분석기
설치·사용·동작 원리 안내서
v1.5.0 · Excel 분석 파일 + PDF 최종 보고서
> 이 안내서는 앞부분에 요약을 싣고, 1장부터 설치, 사용 방법, 동작 원리를 자세히 설명합니다.

## 이 프로그램이 하는 일
MES에서 내려받은 '라인 비가동 현황 조회' Excel 파일을 읽어 고장 기록만 골라냅니다. 기록마다 비고를 읽어 어느 부품이 어떻게 고장 났는지 분류하고, 설비·고장 유형·기간별로 건수와 정지시간을 집계합니다. 결과는 두 파일로 나옵니다. Excel 파일에서는 상세 집계와 원본 기록을 확인하고 필터로 더 분석할 수 있습니다. PDF 보고서에는 핵심 요약, 월별 추이, 설비별 원형 차트, 관리 검토사항이 들어 있어 공유하기 좋습니다.
모든 처리는 이 PC 안에서 끝나며, 외부로 보내는 자료는 없습니다. AI나 학습 기능도 쓰지 않습니다. 분류는 누구나 열어 보고 고칠 수 있는 규칙표를 그대로 따릅니다.

## 처리 순서
단계 | 하는 일 | 예
1. 읽기 | 제목 행을 찾아 열을 맞추고, 빈 행과 합계 행은 건너뜁니다 | 제목 행(7행)을 자동으로 찾음
2. 정리 | 고장 기록을 골라 날짜와 정지시간을 정하고, 제각각인 표기를 통일합니다 | 실러 → 씰러, '후크 교' → '후크 교체'
3. 분류 | 비고에서 부품과 증상을 찾아 규칙표에 따라 고장 유형을 정합니다 | '솔밸브 교체' → 공압·진공 / 솔밸브
4. 집계 | 설비·라인·유형·월별로 건수를 세고 정지시간을 더합니다 | 설비 A: 12건, 340분
5. 보고서 | Excel(15개 시트)과 PDF를 한 번에 만듭니다 | output 폴더에 저장

## 고장 유형을 정하는 방법
비고에는 보통 부품 이름과 그 부품에 생긴 일이 함께 적혀 있습니다. 예를 들어 '인피드 게이트 작동불량 솔밸브교체'에는 게이트와 솔밸브라는 부품 두 개, 그리고 각 부품에 생긴 일(작동불량, 교체)이 들어 있습니다.
프로그램은 부품 이름 뒤에 이어 나오는 증상을 그 부품과 짝짓고, 이 짝을 규칙표에서 찾아 고장 유형을 정합니다. 고장 유형은 대분류·중분류·소분류 3단계입니다. 위의 예는 '공압·진공 > 솔밸브 > 솔밸브 이상/교체'로 분류됩니다.
맞는 규칙이 여러 개면 근거가 분명할 때만 하나를 고르고, 고른 이유를 '분류 근거' 열에 남깁니다. 위의 예에서는 실제로 교체한 부품인 솔밸브를 고릅니다. 근거가 없으면 '검토필요'로 표시해 사람이 판단하게 합니다.

## 고장 유형 체계: 대분류 6개, 규칙 67개
대분류 | 다루는 범위 | 대표 부품
전기·제어 | 센서, 모터, 전원, 제어 장치 | 센서, 모터, 퓨즈, PLC, 서보, 히터
기계 | 움직이는 부품과 구조물 | 베어링, 체인, 벨트, 볼트, 가이드, 컨베어
공압·진공 | 압축 공기나 진공으로 움직이는 부품 | 실린더, 솔밸브, 진공, 에어라인
유체·배관 | 액체가 흐르는 부품과 배관 | 펌프, 밸브, 호스, 오링, 필터, 열교환기
온도·냉각 | 냉동·냉각 설비와 온도 | 냉동기, 냉매, 씰러 온도, 프리저
공정·운전 | 원료와 제품의 흐름, 작업 | 노즐 막힘, 중량 미달, 제품 걸림, 작업자 조작
어느 규칙에도 맞지 않으면 '미분류', 사람이 직접 정하면 '사용자확정'으로 표시합니다. 전체 목록은 4-5절에 있습니다.

## 검토필요란?
사람이 한 번 확인해야 하는 기록입니다. 집계에서 빠지지 않고 건수와 정지시간에 그대로 들어갑니다.
규칙에 맞지 않거나 고장 유형을 하나로 좁힐 수 없는 기록, 정지시간이나 작업일자에 문제가 있는 기록이 여기에 해당합니다. 설비를 '고장대상 설비' 기준으로 집계할 때는 고장대상 설비가 비어 있는 기록도 포함됩니다.
2026년 1~10월 MES 자료(고장 414건)로 확인한 결과, 403건이 자동으로 분류되고 11건이 검토필요로 남았습니다.

## 빠르게 시작하기
1. START.bat을 더블클릭합니다.
2. MES에서 받은 Excel 파일을 프로그램 창에 끌어다 놓습니다.
3. [표준화 + 분석 실행]을 누릅니다.
4. [검토필요] 탭에서 표시된 기록을 확인하고, 필요하면 고칩니다.
5. [Excel + PDF 생성]을 누르면 두 파일이 output 폴더에 저장됩니다.

# 1. 설치

## 어떤 파일을 실행하나요?
상황 | 실행할 파일
Python이 있는 PC | ZIP 압축을 모두 푼 뒤 START.bat 더블클릭
Python이 없는 PC에 줄 EXE 만들기 | Python이 있는 Windows PC에서 BUILD_EXE.bat 실행
EXE를 받은 PC | EquipmentFailureAnalyzer_v1.5.0.exe 더블클릭
프로그램의 원본은 Python 소스이며, EXE는 이 소스로 만듭니다. EXE 파일 이름에는 버전이 붙습니다. 버전이 없는 EquipmentFailureAnalyzer.exe는 이전 빌드이므로 쓰지 마세요.

## Python이 있는 PC
### 1단계: 압축 풀기
배포 ZIP 파일을 바탕화면처럼 파일을 저장할 수 있는 곳에 옮기고 압축을 모두 풉니다. ZIP 안에서 바로 실행하지 마세요.
START.bat, BUILD_EXE.bat, USER_GUIDE.pdf와 core·gui·report·config 폴더가 한 폴더 안에 있어야 합니다.
### 2단계: START.bat 실행
START.bat을 더블클릭합니다. 처음 실행할 때는 설치된 Python을 확인하고, 프로젝트 폴더의 .venv에 전용 실행 환경과 필요한 라이브러리를 설치합니다. 설치가 끝나면 프로그램 창이 열립니다.
지원 환경은 Python 3.11~3.13, 64비트 Windows입니다. 버전이 다르거나 32비트라면 사내 IT 부서에 지원 버전 설치를 요청하세요.
### 3단계: 다음 실행부터
다음부터도 START.bat만 실행하면 됩니다. 설치가 끝나면 인터넷이나 외부 서버 없이도 분석하고 보고서를 만들 수 있습니다.
### 인터넷이 막혀 있다면
처음 설치할 때는 승인된 패키지 저장소에 접속할 수 있거나, 미리 준비한 wheels 묶음이 있어야 합니다. 5장의 '인터넷 없이 설치'를 참고하세요.

## Python이 없는 PC
Python이 없는 PC에 START.bat만 복사하면 실행되지 않습니다. 먼저 Python이 있는 Windows PC에서 EXE를 만들어야 합니다.
### 1단계: Python이 있는 PC에서 확인
START.bat으로 v1.5.0이 열리는지 확인합니다. 샘플 파일로 Excel과 PDF가 모두 만들어지는지 확인한 다음 프로그램을 닫습니다.
### 2단계: BUILD_EXE.bat 실행
BUILD_EXE.bat을 더블클릭합니다. 빌드용 패키지를 설치하고 자동 테스트를 거친 뒤 EXE를 만듭니다. DONE 메시지와 새로 만들어진 파일을 확인하세요.
만들어진 EXE는 START.bat과 같은 폴더에 EquipmentFailureAnalyzer_v(버전).exe라는 이름으로 저장됩니다. 중간에 실패했다면 폴더에 남은 예전 EXE를 최신 버전으로 여기지 마세요.
### 3단계: 복사와 실행
만든 EXE를 이 PC에서 먼저 실행해 본 뒤, 승인된 방법으로 대상 PC에 복사합니다. 대상 PC에서는 EquipmentFailureAnalyzer_v1.5.0.exe를 더블클릭합니다. 대상 PC에 남은 예전 EXE와 바로 가기는 지우세요.
대상 PC에는 프로젝트 폴더나 .venv를 복사하지 않습니다. 기존 설비명과 분류 설정이 필요하면 따로 옮깁니다(5장 참고).
보안 프로그램이 실행을 막으면 보안 설정을 끄지 말고 IT 승인 절차를 따르세요.

# 2. 사용 방법

## 1단계: 입력 파일 등록과 설비명 설정
Excel 파일을 프로그램 창에 끌어다 놓거나 [파일 찾아보기]로 고릅니다. [설비명 변환 설정]에서 설비 코드마다 보고서에 쓸 이름을 입력합니다. 'IF18115 → VITAL#2'는 처음부터 들어 있는 예시입니다.
설비명은 입력을 잠시 멈추거나 창을 닫으면 마지막 값으로 자동 저장됩니다. 이름을 넣지 않은 코드는 보고서에 코드 그대로 나옵니다.

## 2단계: 컬럼 매핑 (필요할 때만)
컬럼 매핑은 작업일자, 설비, 비고 같은 항목을 Excel의 어느 열에서 읽을지 정하는 일입니다. MES에서 내려받은 파일이면 프로그램이 제목 행과 열을 자동으로 찾습니다. 자동으로 맞춘 결과가 틀리면 [컬럼 매핑]에서 고칩니다.
고친 매핑은 제목 행이 같은 파일에 다음부터 자동으로 적용됩니다. 매핑을 바꾸면 이미 저장한 수동 보정도 새 매핑에 맞게 옮겨집니다.

## 3단계: 보고서 설정 (선택)
[보고서 설정]에서 PDF의 제목, 부서, 작성자, 추가 의견을 입력하고 [저장]을 누릅니다. 비워 둔 항목은 보고서에 넣지 않으며, 제목을 비우면 기본 제목을 씁니다.

## 4단계: [Excel + PDF 생성]
불러온 시트와 제목 행, 분석 범위(고장만/전체 비가동), 설비 분석 기준, 기간을 확인한 뒤 [Excel + PDF 생성]을 누릅니다. Excel 파일 이름과 저장 위치를 정하면 PDF도 같은 폴더에 만들어집니다.
저장 창은 START.bat(또는 EXE)이 있는 폴더의 output 폴더에서 열리며, 다른 폴더를 골라도 됩니다. 프로그램 폴더에 저장할 권한이 없으면 %LOCALAPPDATA%\EquipmentFailureAnalyzer\output 폴더를 기본 위치로 씁니다.
입력한 이름 | 만들어지는 파일
분석결과.xlsx | 분석결과.xlsx, 분석결과_최종보고서.pdf
작업이 끝나면 [Excel 열기], [PDF 열기], [결과 폴더]로 바로 열 수 있습니다. 두 파일은 최신 설정으로 다시 집계한 같은 결과를 담고 있습니다.

## 결과 파일 구성
Excel 파일에는 시트 15개가 있습니다.
시트 | 내용
01_종합현황 | 건수·정지시간·평균 요약, 설비별·유형별 상위 그래프, 우선 확인 항목
02_설비별분석 | 설비별 건수·정지시간·비율, 설비마다 고장 유형 원형 차트
03_라인별분석 | 라인별 집계와 그래프
04_유형별분석 | 고장 유형별 집계와 그래프
05_기간별추이 | 월별·주별·일별·연도별 집계와 월별 추이 그래프
06_Pareto | 설비·유형별 건수와 정지시간의 누적 비율
07_교차분석 | 설비별 고장 유형 집계
08_고장상세 | 분석한 기록 전체. 다른 시트의 집계 수식이 모두 이 시트를 참조함
09_검토필요 | 확인할 기록과 검토 사유, 수정 방법, 집계에 미치는 영향
10_데이터품질 | 원본 파일 정보, 분류 상태별 건수, 건너뛴 행, 적용한 설정
11_원본데이터 | 원본 행 그대로 (MES의 생성·수정 사용자 열은 제외)
12_분류기준 | 분석에 쓴 분류 규칙표
13_설비명설정 | 설비 코드와 보고서 설비명
14_TOP고장 | 정지시간이 긴 기록 상위 N건 (화면의 TOP 값, 기본 10건)
15_설비별유형순위 | 설비마다 고장 유형 순위와 원형 차트
PDF는 핵심 분석 결과, 분석 범위와 자료, 설비·고장 유형 비교, 월별 추이, 설비별 상세 분석, 관리 검토사항, 데이터 신뢰성 순서로 구성됩니다.

## 보고서 읽는 기준
설비별 원형 차트의 100%는 그 설비의 전체 분석 기록 건수입니다. PDF에는 상위 5개 유형과 기타를 표시하며, 전체 유형은 Excel에서 확인합니다. 미분류도 전체 건수에 들어갑니다.
설비·라인·유형·교차·기간별 분석표는 정지시간 합계가 큰 순서로 정렬합니다. 추이 그래프는 날짜순입니다. 화면에서 다른 열로 정렬했다면 [큰 값순 정렬]을 눌러 기본 정렬로 되돌립니다.

# 3. 검토필요 처리

## 어떤 기록이 검토필요가 되나요?
사유 | 뜻
미분류 | 비고에서 부품과 증상을 찾지 못함. 행 수정으로 분류를 정하거나 분류 규칙을 보완
복수 유형 후보 | 서로 다른 부품이 함께 적혀 있는데, 하나를 고를 근거가 없음 (예: 가이드 및 후크 조정)
정지시간·일자 문제 | 정지시간이 없거나 형식이 틀림, 작업일자가 없음, 종료 시각이 시작 시각보다 이름, 입력한 정지시간과 시작·종료 차이가 2분 넘게 다름
고장대상 미기재 | 설비 분석 기준이 '고장대상 설비'일 때만 검토필요. 다른 기준에서는 참고 정보로만 표시
검토필요는 집계에서 빠진 기록이 아닙니다. 건수와 정지시간에 포함되며, 복수 유형 후보는 우선순위가 가장 높은 유형으로 임시 집계됩니다.
고장 유형을 정하는 자세한 기준은 4-4절에 있습니다.

## 행 수정 (선택 행 수동 수정)
[고장 상세]나 [검토필요] 탭에서 행을 고르고 [선택 행 수동 수정]을 누릅니다. 수정 창에는 검토 사유, 수정 방법, 분류 근거와 후보, 이미 저장된 보정 내용이 나옵니다.
바꾼 항목만 저장됩니다. 정지시간이나 작업일자만 고치면 분류는 저장되지 않으므로, 복수 유형 후보 표시는 그대로 남습니다.
지금 표시된 분류를 그대로 확정하려면 '위 대·중·소분류를 사용자확정으로 저장'에 체크합니다. 분류 칸을 고치면 자동으로 체크됩니다.
저장한 값을 지우고 다시 저장하면 그 항목만 해제됩니다. [수동 보정 해제]를 누르면 그 기록의 보정이 모두 해제됩니다. 저장하면 자동으로 다시 분석하지만, Excel과 PDF는 다시 만들어야 바뀐 내용이 들어갑니다.

## 분류 규칙 편집
[분류기준 관리]에서 규칙을 추가하거나 고칩니다. 각 열의 뜻은 4-4절에 있습니다.
context와 symptom 칸에는 찾을 말을 '|'로 구분해 적습니다(예: 솔밸브|솔레노이드). 이 칸은 정규식이라는 검색 형식을 따르므로 괄호, 물음표, 점 같은 기호에는 특별한 뜻이 있습니다. 비고에서 띄어쓰기를 지운 뒤 찾으므로, 찾을 말에도 띄어쓰기를 넣지 않습니다. symptom에 '.'만 적으면 부품어만 나와도 규칙이 맞습니다.
role 칸에는 규칙 종류를 적습니다. component는 부품 규칙, fallback은 부품 이름이 없을 때만 쓰는 부위 미기재 규칙, override는 작업자 조작처럼 원인을 바로 정하는 규칙입니다.

# 4. 동작 원리
이 장에서는 프로그램이 MES 자료를 어떤 순서로 처리하고, 고장 유형을 어떤 기준으로 정하는지 설명합니다. 처리 순서는 읽기 → 정리 → 분류 → 집계 → 보고서입니다.

## 4-2 Excel 읽기
- 제목 행 찾기: 처음 60행 가운데 '비가동 시작 시간', '설비', '비고'처럼 미리 등록된 열 이름이 가장 많은 행을 제목 행으로 봅니다.
- 열 맞추기: 열 이름은 띄어쓰기와 대소문자를 무시하고 비교합니다. 항목마다 받아들이는 열 이름 목록(column_mapping.json)이 있습니다.
- MES 형식 인식: '비가동 시간(분)', '비가동 코드(중)', '비가동 유형' 열이 모두 있으면 MES 비가동 목록으로 보고, 고장대상 설비 판정처럼 MES에만 맞는 처리를 적용합니다.
- 건너뛰는 행: 빈 행, 중간에 다시 나오는 제목 행, '합계'·'총계'·'소계'로 시작하는 행은 건너뜁니다. 건너뛴 행은 모두 10_데이터품질 시트에 남습니다.
- 병합된 셀: 원본에서 실제로 병합한 범위에만 값을 채웁니다. 그냥 비어 있는 칸을 위 칸 값으로 채우지 않습니다.
항목 | MES 열 | 쓰임

시작·종료 시각 | 비가동 시작 시간, 비가동 종료 시간 | 정지시간 검증
정지시간 | 비가동 시간(분) | 정지시간 합계

비고 | 비고 | 고장 유형 분류

## 4-3 기록 정리
분류하기 전에 기록마다 다음 일곱 가지를 정리합니다.
- 고장 여부: 비가동 유형이 '고장'(코드 TR)이면 고장 기록입니다. 계획운휴(PI)와 작업운휴(WI)는 원본데이터 시트에는 남기지만, 분석 범위가 '고장만'이면 집계에서 뺍니다.
- 날짜: 2026-01-02, 20260102, 2026.01.02, 2026년 1월 2일, Excel 날짜 숫자를 모두 같은 날짜로 읽습니다.
- 정지시간: MES의 '비가동 시간(분)' 값을 먼저 씁니다. 이 값이 비어 있으면 종료 시각에서 시작 시각을 뺀 시간을 씁니다. 두 값이 2분 넘게 다르면 검토필요로 표시합니다. 자정을 넘긴 정지도 제대로 계산합니다.
- 설비명: 설비 코드(예: IF18115)는 [설비명 변환 설정]에서 정한 이름(예: VITAL#2)으로 표시합니다. 이름을 정하지 않은 코드는 코드 그대로 둡니다. 프로그램이 이름을 짐작해 붙이지 않습니다.
- 고장대상 설비: MES의 '비가동 코드(중)' 값이 1P, 2P, 3P처럼 공장 구분으로 시작하면(예: 3P I/C AJ-10 제대기) 그 값을 고장대상 설비로 봅니다. 그 밖의 값이면 고장대상이 입력되지 않은 것으로 봅니다.
- 비고 정리: 영문은 소문자로 바꾸고, 겹친 띄어쓰기는 하나로 줄입니다. 같은 말을 다르게 쓴 표기 80가지를 하나로 맞춥니다(실러 → 씰러, 벨브 → 밸브, 컨베이어 → 컨베어, 솔레노이드 벨브 → 솔밸브 등). 또 MES 입력란은 끝 글자가 잘린 경우가 많아, 구절 끝에 혼자 남은 글자 15가지를 원래 말로 되살립니다('교' → '교체', '고' → '고장', '조' → '조정' 등). 원래 비고는 그대로 두고, 정리한 문장은 '정규화 내용' 열에 따로 저장합니다.
- 기록 ID: 기록 내용으로 기록마다 고유한 ID를 만듭니다. 사람의 지문처럼, 내용이 같으면 언제나 같은 ID가 나옵니다. 수동 보정은 이 ID에 연결해 저장하므로, 같은 자료를 다시 불러와 분석해도 보정이 그대로 적용됩니다. 내용이 완전히 같은 기록이 여러 개면 '동일 기록 후보'로 표시합니다.

## 4-4 고장 분류 원리
### 규칙의 구성
규칙 하나는 '이 부품어 뒤에 이 증상어가 나오면 이 고장 유형'이라는 뜻입니다. 부품어는 부품을 가리키는 말, 증상어는 그 부품에 생긴 일을 나타내는 말입니다. 규칙표([분류기준 관리] 또는 Excel의 12_분류기준 시트)의 열은 다음과 같습니다.
열 | 뜻 | 예 (솔밸브 규칙)
context (부품어) | 부품을 가리키는 말 | 솔밸브, 솔레노이드, 전자변
symptom (증상어) | 부품에 생긴 일 | 고장, 소손, 망가짐, 교체
exclude (제외어) | 이 말이 있으면 규칙을 적용하지 않음 | 센서 규칙의 '센서 정상', '센서 이상 없음'
priority (우선순위) | 한 부품에 규칙 두 개가 맞으면 숫자가 큰 쪽이 우선 | 88
role (규칙 종류) | 부품 규칙, 부위 미기재 규칙, 원인 규칙 가운데 하나 | component
major·middle·minor | 붙일 고장 유형(대·중·소분류) | 공압·진공 / 솔밸브 / 솔밸브 이상/교체
규칙은 쓰임에 따라 세 종류로 나뉩니다.
- 부품 규칙(54개): 부품 이름이 적혀 있을 때 씁니다.
- 부위 미기재 규칙(11개): '파손', '이탈', '포장기 트러블'처럼 부품 없이 증상이나 설비만 적힌 기록에 씁니다. 부품 규칙이 하나라도 맞으면 쓰지 않습니다.
- 원인 규칙(2개): 원인이 분명히 적힌 기록에 씁니다. '작업자가 …'처럼 작업자 조작이 적힌 기록은 작업자 조작 기인으로, '개선 test'처럼 고장이 아닌 작업이 적힌 기록은 개선·시험 작업(고장 아님)으로 바로 정합니다.

### 1단계: 구절로 나누기
비고를 줄바꿈, 빗금(/), 괄호, 문장 끝 마침표, ' - ', 화살표가 있는 곳에서 나눕니다. 나눈 구절 안에서는 띄어쓰기를 지우므로 '센서 교체'와 '센서교체'를 같은 말로 봅니다. '1.3.5번'처럼 숫자 사이에 찍힌 점에서는 나누지 않습니다.

### 2단계: 부품과 증상 짝짓기
부품어를 찾으면 그 뒤에서 증상어를 찾습니다. 찾는 범위는 15자 이내이고, 다음 부품어가 나오면 거기서 멈춥니다.
예를 들어 '제함기 푸셔 실린더 센서 교체'에서 푸셔의 증상 찾기는 실린더 앞에서, 실린더의 증상 찾기는 센서 앞에서 멈춥니다. 뒤에 '교체'가 붙은 부품은 센서뿐이므로 센서·검출로 분류합니다.
이 밖에도 다음 기준을 따릅니다.
- 부정하는 말은 증상으로 보지 않습니다. '센서 이상 없음, 모터 트립'은 센서가 아니라 모터로 분류합니다.
- 장소를 나타내는 말은 고장 부품으로 보지 않습니다. '트레이 체인 메인, 보조 스프라켓에서 이탈'에서 스프라켓은 체인이 빠진 위치이므로 체인으로 분류합니다.
- '및', '와/과', 쉼표로 이어 쓴 부품은 뒤에 오는 증상을 함께 받습니다.
- 부품어가 없는 구절은 바로 앞 구절에 나온 부품의 설명이 이어지는 것으로 봅니다. '로드리스 실린더 파손/교체'에서 '교체'는 실린더에 붙습니다.
- 부품 이름 속에 든 말은 증상으로 보지 않습니다. '고정볼트'의 '고정'은 조치가 아니라 부품 이름의 일부입니다.

### 3단계: 증상어의 세 종류
증상어는 부품이 실제로 고장 났다는 근거가 얼마나 확실한지에 따라 세 종류로 나눕니다.
종류 | 예 | 근거 강도
교체·수리 | 교체, 교환, 수리, 정비, 가공, A급, 신규 | 가장 강함. 실제로 문제가 있던 부품을 가리킴
고장 증상 | 고장, 파손, 에러, 작동불량, 마모, 이탈, 누수 등 | 중간
조정·점검 | 조정, 점검, 청소, 위치, 타이밍 등 | 가장 약함

### 4단계: 후보가 여럿일 때 하나 고르기
맞는 규칙이 둘 이상이고 고장 유형이 서로 다르면 아래 순서대로 확인합니다. 후보가 하나로 좁혀지는 단계에서 바로 멈춥니다.
순서 | 확인하는 것 | 예 → 결과
1 | 원인 규칙이 맞았는가 | '작업자가 … 위치 틀려짐' → 작업자 조작 기인
2 | 후보가 모두 같은 유형인가 | 그 유형으로 정함
3 | 부품 규칙과 부위 미기재 규칙이 함께 맞았는가. 부품 규칙이 우선이며, 부위 미기재 규칙만 맞았으면 우선순위가 높은 쪽을 고름 | '봉함기 롤러부 파손' → 롤러·브러쉬
4 | 한 부품에 규칙 두 개가 맞았는가. 우선순위가 높은 세부 규칙을 고름 | '엔드씰러 온도 에러' → 씰러 온도
5 | 부품 이름이 겹치는가. 증상에 가장 가깝고 더 구체적인 이름을 고름 | '진공펌프 이상작동' → 진공·석션
6 | 근거가 더 강한 쪽이 있는가. 교체와 고장 증상이 함께 적힌 부품 > 교체 > 고장 증상 > 조정만 | '게이트 작동불량 솔밸브교체' → 솔밸브
7 | 원인을 나타내는 연결 표현이 있는가 ('…으로/로 (인해)', '…되어', '…하며' 등) | '정전 발생으로 냉동기 다운' → 전원·차단기
8 | 작업자가 MES에서 고른 부위 구분(비가동 코드(소))과 맞는 후보가 있는가 | '실린더 작동 이상 / 레일 간섭' + 기계파트 → 가이드·레일
9 | 그래도 정할 수 없음 | 검토필요. 우선순위가 가장 높은 후보를 임시로 표시 (예: '가이드 및 후크 조정')
자동으로 골랐으면 '분류 근거' 열에 규칙 ID, 일치한 말, '자동선택: 사유'가 남습니다. '후보 규칙' 열에는 맞았던 규칙이 모두 나옵니다.
8번에서 쓰는 MES 부위 구분과 대분류의 관계는 다음과 같습니다.
MES 부위 구분 | 맞는 대분류

### 분류가 하지 않는 일
- 고장 원인을 확정하지 않습니다. 비고에 적힌 부품과 증상을 기준으로 나눌 뿐입니다.
- 뜻을 짐작하지 않습니다. 규칙에 없는 말만 있으면 미분류로 남깁니다.
- 수동 보정은 그 기록 하나에만 적용합니다. 비슷한 문장에 자동으로 퍼뜨리지 않습니다.

## 4-6 집계 방법
- 원본 1행을 기록 1건으로 셉니다. 이어지는 기록을 임의로 합치지 않습니다.
- 정지시간은 기록별 시간을 더한 값입니다. 여러 라인이 같은 시간에 멈춘 부분을 빼지 않으므로, 공장 전체가 실제로 멈춘 시간과는 다릅니다.
- 건수 비율은 '해당 항목 건수 ÷ 전체 건수', 시간 비율은 '해당 항목 정지시간 ÷ 전체 정지시간'입니다.
- 정지시간이 없는 기록은 건수에는 넣고, 시간 합계와 평균에서는 뺍니다. 작업일자가 없는 기록은 기간별 추이에서 뺍니다.
- 분석표는 정지시간이 큰 순서로 놓고, 정지시간이 같으면 건수가 많은 순서로 놓습니다. 설비별 유형순위는 건수가 많은 순서입니다.
- 원형 차트는 상위 5개 유형과 나머지를 합친 '기타'로 그립니다. 100%는 그 설비의 전체 기록 건수이며, 미분류도 들어갑니다.
- 검토필요 기록도 모든 집계에 들어갑니다.
- 가동시간이나 생산량 자료가 없으므로 고장률, MTBF(평균 고장 간격), MTTR(평균 수리 시간)은 계산하지 않습니다.
- Excel의 집계 칸은 08_고장상세 시트를 참조하는 수식입니다. 상세 시트의 값을 고치면 집계도 따라 바뀝니다.
설비를 어떤 기준으로 묶을지는 화면의 [설비 분석 기준]에서 고릅니다.
기준 | 묶는 방법
사용자 지정 설비명(코드 기준) | MES 설비 코드로 묶고, 정한 이름으로 표시 (기본값)
고장대상 설비 | 비가동 코드(중)의 설비로 묶음. 비어 있으면 '라인 / 고장대상 미기재'로 묶음
등록 설비 | MES 설비명 그대로 묶음
설비군(후보) | 비고에 나온 말로 짐작한 설비 묶음. 확정된 설비가 아님

## 4-7 데이터 구조
프로그램이 다루는 개념과 개념 사이의 관계를 정리하면 다음과 같습니다.
개념 | 뜻 | 관계
원본 행 | MES Excel의 한 줄 | 기록 1건이 됨
기록 | 비가동 한 건. 날짜, 정지시간, 라인, 설비, 비고를 담음 | 비가동 유형과 기록 ID가 하나씩 있음
비가동 유형 | 고장, 계획운휴, 작업운휴 | 고장만 분류함
라인 | 생산 라인 | 여러 설비가 속함
설비 | MES에 등록된 설비(코드) | 보고서에는 정한 이름으로 표시
고장대상 설비 | 비가동 코드(중)에 적힌 설비 | 등록 설비와 다를 수 있음
고장 유형 | 대분류 > 중분류 > 소분류 | 규칙이나 사람이 정함
규칙 | 부품어 + 증상어 → 고장 유형 | 규칙표에 67개
분류 상태 | 규칙분류, 검토필요, 미분류, 사용자확정, 분류대상 외 | 기록마다 하나
분류 근거 | 맞은 규칙, 일치한 말, 자동선택 사유 | '분류 근거' 열에 표시
수동 보정 | 사람이 고친 값 | 기록 ID로 연결
분류 상태별 뜻과 집계 방식은 다음과 같습니다.
상태 | 뜻 | 집계
규칙분류 | 규칙 하나가 맞았거나, 근거를 남기고 자동으로 고름 | 분류된 유형으로 집계
검토필요 | 후보가 여럿인데 하나를 고를 근거가 부족함 | 임시 1순위 유형으로 집계
미분류 | 맞는 규칙이 없음 | '미분류' 유형으로 집계
사용자확정 | 사람이 행 수정에서 확정함 | 확정한 유형으로 집계
분류대상 외 | 고장이 아닌 비가동. 분석 범위가 '전체 비가동'일 때만 나옴 | '분류대상 외'라는 이름으로 건수와 시간을 집계
정지시간·작업일자에 문제가 있는 기록은 분류 상태와 관계없이 [검토필요] 탭에 함께 나옵니다.

## 4-8 안전장치
- 원본 Excel은 읽기만 합니다. 보고서를 원본과 같은 파일 이름으로 저장할 수 없습니다.
- 원본의 글자는 글자로만 저장하므로 Excel 수식으로 실행되지 않습니다.
- MES의 생성·수정 사용자 열은 보고서에 넣지 않습니다.
- 설정을 저장할 때는 이전 파일을 백업합니다.
- 새 버전을 처음 실행하면 직접 고치지 않은 기본 규칙만 새 규칙으로 바꾸고, 직접 고친 규칙은 그대로 둡니다. 바꾸기 전 설정은 config\backup 폴더에 백업합니다.
- v1.4.0 이하 프로그램은 새 규칙을 잘못 읽지 않도록 안내 메시지를 띄우고 멈춥니다.

# 5. 업데이트·문제 해결

## 새 버전 설치와 기존 설정 유지
프로그램을 닫고, 새 ZIP의 압축을 새 폴더에 푼 뒤 START.bat을 실행하세요. 같은 Windows 사용자의 아래 설정 폴더를 지우지 않으면 설비명과 설정이 그대로 남습니다.
%LOCALAPPDATA%\EquipmentFailureAnalyzer\config
새 버전을 처음 실행하면 기본 분류 규칙, 표기 정규화, 설비군, 설정을 자동으로 합칩니다. 직접 고치지 않은 기본값은 새 버전 값으로 바뀌고, 직접 고치거나 추가하거나 삭제한 규칙은 그대로 둡니다. 합치기 전 파일은 config\backup\날짜_시각 폴더에 백업되고, 결과는 상태 표시줄에 나옵니다.
한 PC에 설치한 모든 버전이 이 설정 폴더를 함께 씁니다. v1.5.0 이상을 한 번 실행한 뒤 v1.4.0 이하 프로그램을 열면 "이 분류 규칙은 v1.5.0 이상 전용입니다"라는 안내가 나오고 프로그램이 멈춥니다. 예전 프로그램이 새 규칙을 읽어 잘못 분류하는 일(검토필요 급증)을 막기 위한 동작이므로 최신 버전으로 실행하세요.
v1.5.0에서 달라진 점은 docs\UPDATE_v1.5.0.txt에 정리되어 있습니다.

## 다른 PC로 설정 옮기기
양쪽 PC에서 프로그램을 닫고 config 폴더를 백업한 뒤 옮기세요. 자동으로 동기화되지 않습니다.
파일 | 내용
equipment_names.json | 설비명
manual_overrides.json | 수동 보정
column_overrides.json | 컬럼 매핑
classification_config.xlsx | 분류 규칙
final_report.json | PDF 설정

## 인터넷 없이 설치
Windows와 Python의 버전·비트가 같은 PC에서 prepare_wheels.bat을 실행해 필요한 파일을 모읍니다. 만들어진 wheels 폴더 전체를 대상 PC의 프로젝트 폴더 안 wheels 폴더로 옮긴 뒤 START.bat을 실행합니다. 일부 패키지만 있으면 설치에 실패합니다.

## 자주 생기는 문제
증상 | 조치
PDF 모듈이 없다는 오류 | START.bat이나 setup.bat을 실행해 reportlab을 설치. 인터넷이 막혀 있으면 wheels를 새로 준비
저장 실패 | Excel과 PDF를 모두 닫고 다른 이름으로 저장. 저장 폴더 권한 확인
한글 PDF 글꼴 오류 | Windows에 맑은 고딕이 있는지 확인. 필요하면 final_report.json의 font_path에 승인된 한글 TTF 경로 지정
분류가 예전과 다름 | v1.5.0 규칙으로 합쳐진 결과. 이전 규칙은 config\backup 폴더에 있음
"v1.5.0 이상 전용" 시작 오류 | 예전 EXE를 실행한 경우. START.bat이나 버전이 붙은 최신 EXE로 실행
제목이나 설비명이 예전 값 | 설정을 저장한 뒤 [Excel + PDF 생성]으로 다시 만들기. 이미 만든 파일은 자동으로 바뀌지 않음
오류 기록(로그) 위치: %LOCALAPPDATA%\EquipmentFailureAnalyzer\logs\application.log
확인 범위: 자동 테스트 121개가 통과했고(화면 테스트 포함), 실제 MES 파일(고장 414건)로 Excel과 PDF가 만들어지는 것을 확인했습니다. EXE가 다른 PC에서 잘 실행되는지는 따로 확인해야 합니다.
