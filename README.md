# 설비 고장 분석기 v1.16.0

MES 비가동 내보내기(Excel)를 읽어 고장 기록을 표준 유형으로 분류하고, Excel 분석파일(기본 11개 시트, 제품 자료가 있으면 12개), PDF 최종보고서, 원본 검토표시 사본을 함께 만드는 오프라인 Windows 프로그램입니다. 분류는 로컬 규칙 기반이며 외부 전송이나 LLM을 쓰지 않습니다.

## 한 이력, 하나의 최종 분류

- **고장 분야 / 상세설비·모듈 / 부품군 → 세부 부품 / 고장 현상**으로 분류하며 **조치**는 별도 보존합니다. 공개 분류 필드는 기존 네 항목을 유지하고, 부품군은 선택한 부품에 따라 표시합니다. 예: `기계 / 컨베어 / 베어링·부싱 → 베어링(종류 미상) / 마모`, 조치 `교체`. 한 고장이력에 최종 분류 하나만 저장하며, 미확정 분류 열은 빈칸으로 두고 판정은 상태·사유에 표시합니다.
- 상세설비는 고장·조치 근거가 붙은 원문과 비가동코드(중)를 확인해 표준화합니다. 등록 설비명만으로 실제 고장 설비를 추정하지 않으며, 근거가 없으면 `상세설비 미상`으로 남깁니다. 설비 판정 근거와 원본 설비명·코드는 별도로 보존합니다.
- **고장 분야·상세설비·세부 부품·고장 현상은 독립 선택**합니다. 부품군은 종류를 찾는 탐색 기준입니다. 다른 축을 바꿔도 기존 선택을 유지하고, 분야는 부품의 소속보다 실제 현상을 기준으로 확인합니다. `모터 소손`은 전기·제어, 기계적 마모는 기계로 구별합니다.
- 교체·수리·조정·점검·청소·급유·체결·리셋 등은 고장 현상으로 넣지 않고 표준 조치 7종으로 별도 관리합니다. 단일 부품의 조치만 기재된 기록은 부품과 조치를 자동 보존하고 고장 현상은 `현상 미기재`로 표시합니다. 마모나 파손을 추정하지 않습니다. 차단기 `떨어짐`은 `보호장치 동작`으로 처리하고 낙하나 과부하를 추정하지 않습니다.
- 상세설비 본체만 적힌 기록은 세부 부품에 본체명을 반복하지 않고 `세부 부품 미기재`로 표시합니다. 해당 기록과 `제품·자재` 대상은 전체 이력·정지시간에는 포함하고 실제 부품 발생 건수에서는 제외합니다. 종류가 없는 부품은 `(종류 미상)`을 보존하며 구체적인 종류를 추정하지 않습니다.
- **완전 자동분류 / 부분 자동분류 / 검토필요를 구분**합니다. 네 분류축이 모두 확인되면 완전 자동분류하고, 단일 대상의 일부 정보만 없으면 확인된 항목을 부분분류로 보존합니다. `미기재 분류 항목`에서 부족한 정보를 확인할 수 있으며, 원문에 없는 정보를 작업자가 추측하도록 요구하지 않습니다. 의심·대안, 미등록 다른 물리 고장, 고장 대상이 불명확한 공동주어, 같은 명사의 동률 상충 규칙, 부품명만 있는 기록과 데이터 품질 문제는 검토필요에 남깁니다.
- 종합현황과 Excel·PDF에 완전 자동분류, 부분 자동분류, 실제 검토 대상을 별도로 표시합니다. 자동처리 합계는 완전+부분이며, 부분분류에서도 시간·일자 품질 문제가 있으면 검토 목록에 포함할 수 있습니다. 부분분류의 조치만 수정할 때는 고장 현상을 재확정할 필요가 없습니다.
- 한 부품의 명확한 실제 고장은 후속 조치보다 먼저 선택합니다. 그래도 여러 부품·현상·설비 후보가 남으면 원문 고장 또는 완료 조치 근거가 있는 **1순위 후보를 이력 대표로 자동 선택**하고 사유에 `1순위 대표 자동선택`을 표시합니다. 원문과 모든 후보는 보존합니다. 의심·대안, 미등록 다른 물리 고장 등 보호 조건은 자동 선택에서 제외합니다.
- 표준화는 문맥이 있는 TC·카플링 같은 별칭을 보완하되, 냉각수 리크를 수리로 읽거나 교체 요청·미완료·대기를 완료 작업으로 처리하지 않습니다. 뒤에 언급된 다른 설비를 앞쪽 부품의 위치로 붙이지 않습니다.
- 예를 들어 `실린더 및 베어링 손상`은 원문의 두 고장 후보를 보존하면서 대표 하나를 자동 선택해 사건과 정지시간을 한 번만 집계합니다. 후보 순위는 규칙 근거에 따른 순서이며 정확도나 확률이 아닙니다. 대표 선택은 다른 실제 고장이 없다는 뜻이 아니며, 부품별 건수도 모든 고장 부품의 총수가 아닌 선택된 대표 부품의 기록 수입니다.
- [검토필요] 그리드에서 대분류·상세설비·세부 부품·소분류를 연속 선택하면 다음 분류, 다음 행으로 자동 이동합니다. 행별 저장 버튼 없이 메모리에 `확정 대기`로 표시하며, [표준화 + 분석 실행]에서 현재 파일의 대기 분류를 한 번에 확정·저장합니다. 입력 중에는 기준 엑셀을 다시 읽거나 임시 파일을 저장하지 않고 바뀐 행만 갱신합니다. 프로그램을 닫으면 미확정 선택은 사라집니다. 분류명은 자유 입력하지 않습니다.
- 과거 복수 분류와 수동 복수 보정은 후보 근거로 보존합니다. 첫 번째 항목을 임의로 채택하지 않으며, 하나의 최종 분류를 다시 선택해야 합니다.
- **07_고장이력과 08_부품증상상세는 모두 이력당 한 행**입니다. 08에는 검토필요·미일치·분류 없는 고장도 빠짐없이 남습니다.
- 전체 건수와 정지시간은 원본 기록당 한 번만 집계합니다. 부품별 건수에는 최종 단일 부품만 포함하고 미확정 후보는 제외합니다. 부품 비율은 전체 고장기록을 분모로 하므로 미확정이 있으면 합계가 100%보다 작을 수 있습니다.
- [Excel + PDF 생성]은 검토필요·미확정 분류가 남아 있어도 저장됩니다. `09_검토품질`은 원본 행·원문·최종 분류·부품군·별도 조치와 후보를 표시합니다. 정답을 작성해 전달하면 규칙 보완 자료로 활용할 수 있습니다. Excel 수정값은 프로그램에 자동 반영되지 않습니다. 품질 집계·분석 조건은 `11_기준정보`, 이력 ID·상세 후보 근거는 `07_고장이력`에서 확인합니다.

기본 11개·제품 자료가 있으면 12개 시트로 통합한 구조는 유지합니다. 초기 기능부터 현재까지의 요약 연혁은 [Release Notes](docs/RELEASE_NOTES.md), 이전 버전별 상세 기능 변경은 [변경 이력](docs/CHANGELOG.md), 각 시트의 관리자 활용법은 [보고서 시트 검수 내역](docs/REPORT_SHEET_REVIEW.md)을 참고하세요.

## 실행

최종 분류 선택 화면에서 원문 바로 오른쪽의 표준화 후 내용을 비교할 수 있습니다. 표준화 규칙을 변경했다면 분석을 다시 실행하세요. 일반 보드는 제어기판·카드(종류 미상)로 분류하고, 점도 현상만 있는 기록은 원인 부품을 추정하지 않고 검토에 남깁니다.

ZIP을 모두 풀거나 저장소를 내려받은 후 프로젝트 폴더의 **START.bat**을 더블클릭하세요. Python 3.11~3.13 (64-bit)이 필요합니다.
최초 실행은 인터넷 또는 wheels 폴더의 사전 준비 파일로 라이브러리를 프로젝트 폴더의 .venv에 설치합니다. 설치 후에는 오프라인으로 동작합니다.

Python이 없는 현장 PC용: 준비된 Windows PC에서 **BUILD_EXE.bat**을 실행하면 테스트 후 프로젝트 폴더에 **EquipmentFailureAnalyzer_v1.16.0.exe**처럼 버전이 붙은 EXE가 생성됩니다.
버전이 없는 `EquipmentFailureAnalyzer.exe`는 v1.4.0 이하의 이전 빌드입니다. 사내 설치·배포는 IT 정책을 따르세요.

**업데이트 실행 버전:** 한 PC의 모든 버전이 같은 사용자 설정을 공유합니다. 새 대표 자동선택 정책은 최신 START.bat 또는 v1.16.0 이상 EXE로 실행하세요. 현재 규칙의 schema 7을 지원하는 이전 EXE는 이전 판정 정책으로 동작하며, schema 7을 지원하지 않는 구버전은 규칙 읽기가 차단됩니다. 현재 v3 기준의 수동확정값은 그대로 적용합니다. 그보다 이전 스키마의 수동확정 파일은 보존하고 이전 분류를 재검토 후보로 표시합니다. 과거 소분류 `교체`도 새 고장 현상으로 자동 확정하지 않습니다.

## 사용 순서

Excel 드래그 앤 드롭 / 파일 찾아보기 -> (필요 시) [컬럼 매핑] -> [기준정보 · 설정 → 설비명 변환 설정] -> 분석 -> [검토필요] 표에서 확인·수정 -> [Excel + PDF 생성]

설비명 변환·분류기준·설정 폴더는 상단 [기준정보 · 설정] 메뉴에서 엽니다. [파일 · 분석 조건]을 누르면 입력 파일과 분석 조건을 펼치거나 접을 수 있습니다. [검토필요] 또는 [상세분석 → 전체 기록 · 수정]에서 셀을 더블클릭하거나 F2로 편집하며, 일반 값은 Enter 또는 다른 셀 클릭으로 저장하고 Esc로 취소합니다. 행 우클릭 메뉴의 [분류 보정 해제]는 시간·일자·고장대상·제품 보정을 유지하며, [이 기록의 수동 보정 모두 해제]는 해당 기록의 보정을 모두 해제합니다. 저장하면 분석표를 갱신하며, Excel·PDF에는 보고서를 다시 생성한 뒤 반영됩니다.

[검토필요] 표의 좌상단 빈 칸을 클릭하면 현재 표시된 열과 검색 결과의 모든 행을 제목 포함으로 복사합니다. 후보 비교가 필요하면 최종 분류 셀에서 창을 열고 후보를 더블클릭하거나 Enter로 선택할 수 있습니다. 창은 중앙에 열리며 제목 표시줄로 이동합니다. 분류 입력 중 정렬·검색 결과는 유지하고, 제목이나 검색어를 다시 조작할 때 재정렬·필터링합니다. 시간·일자·제품·대상설비는 기존처럼 바로 저장·재분석합니다.

[설비명 변환 설정]의 기본 명명 기준은 **라인 코드(C열)**입니다. 라인별 보고서 설비명을 입력하며, 기존 **설비 코드(E열)** 변환표는 별도로 보존하고 선택할 수 있습니다. 열 위치가 다른 파일은 [컬럼 매핑]에서 라인 코드 열을 지정합니다. 라인 열이 없는 파일은 기존 설비 코드 기준을 사용합니다.
같은 창의 **설비군 규칙**에서 구분자를 `#`로 두면 `A#1(1호기)`, `A#2`를 `A` 설비군으로 묶습니다. 설비군 열에서 개별 값을 지정하거나 구분자를 변경할 수 있습니다. 상단 **설비 분석 기준 → 설비군(이름 기준)**을 선택하면 해당 설비군별로 화면과 Excel·PDF를 집계합니다. 기본 **사용자 지정 설비명** 기준에서는 호기별 이름을 유지합니다.
같은 표의 **공장 / 팀**도 직접 입력할 수 있습니다. 공장 기본값은 원본 라인명 `[공장명]`에서 자동으로 읽으며, 직접 입력한 공장명이 우선합니다. 공장 입력을 비우면 자동값으로 돌아가고, 팀은 직접 지정합니다. 설정은 다음 실행에도 유지됩니다. **설비 분석 기준 → 공장 / 팀**을 선택하면 공장별 또는 공장·팀별로 집계하며, Excel 설정·상세 시트와 PDF에도 반영됩니다.

상단 **공장 필터 / 팀 필터**에서 분석할 대상을 선택합니다. 기본값은 **전체 공장 / 전체 팀**이며, 공장을 선택하면 해당 공장의 팀 목록을 보여줍니다. 미기재 항목도 선택할 수 있습니다. 선택한 공장·팀은 분석 범위·기간·중복 제외 조건과 함께 적용되며, 화면 집계와 Excel·PDF, 원본 사본의 검토표시에 동일하게 반영됩니다. 설비 분석 기준은 집계 단위를 정하고 공장·팀 필터는 분석 대상을 정합니다.

[기준정보 · 설정 → 검토필요 색상 설정]에서 **복수검토 → 규칙 미일치 → 비가동코드 미기입 → 기타** 네 유형의 셀 배경색을 지정합니다. 기타에는 정지시간·일자·고장대상 이상 등 나머지 품질 검토 사유가 포함되며, 기존 검토 판정 기준은 유지됩니다. 저장한 색상은 다음 실행에도 유지됩니다.
[Excel + PDF 생성]은 분석 엑셀, 최종보고서 PDF, `결과이름_원본_검토표시.xlsx`를 함께 저장합니다(원본이 `.xlsm`이면 검토표시 사본도 `.xlsm`). 검토표시 사본은 현재 분석 범위의 검토필요 원본 행 A:X 전체를 한 가지 대표 배경색으로 표시하며, 입력 원본을 덮어쓰지 않습니다. 한 행에 여러 검토 사유가 있으면 위 네 유형 순서에서 가장 앞선 유형의 색상을 적용합니다. 행마다 메모 하나에 모든 사유를 남기며 기존 메모는 보존합니다.

지원: .xlsx/.xlsm. 매크로는 실행하지 않습니다. .xls/암호화 파일은 미지원입니다. 시트나 제목 행을 바꾼 후에는 [시트 읽기]를 누르세요.

CLI: `python analyze_cli.py INPUT.xlsx --output OUTPUT.xlsx [--basis target] [--overwrite]`

라인 이름·설비군 CLI 예: `python analyze_cli.py INPUT.xlsx --output OUTPUT.xlsx --name-source line --set-name "LINE01=A#1" --set-name "LINE02=A#2" --basis group`

공장·팀 필터 CLI 예: `python analyze_cli.py INPUT.xlsx --output OUTPUT.xlsx --factory "서울공장" --team "포장팀"`

## 분류·집계 기준

- 기본은 고장만 집계하며 계획운휴/작업운휴는 제외합니다. 1행=1기록. 시간 미기재를 0분으로 보지 않습니다.
- 생산량/가동시간/실수리시간 없이 고장률·MTBF·MTTR를 만들지 않습니다.
- 유형은 비고에 기록된 부품·증상 조건과 결정 규칙으로 분류하며 원인 확정이 아닙니다. 복수 후보는 원문 근거에 따라 대표 하나를 자동 선택하고, 의심·대안·미등록 다른 고장 등 보호 조건은 검토필요로 남깁니다.
- 화면·보고서의 최종 분류는 고장 분야 / 상세설비·모듈 / 세부 부품 / 고장 현상이며 부품군과 조치는 별도 열입니다. 출력 스키마는 `equipment_part_failure_v3`입니다. 부품 식별용 내부 분야 / 부품군 / 부품 종류 경로는 공개 분류축과 구별합니다. 상세설비 표준명·별칭은 카탈로그의 `equipment_types`에서 관리합니다. 비가동코드(중)의 설비명이 고장내용에 반복됐더라도 자체 고장·조치 근거가 없으면 부품 후보에서 제외합니다.
- 검토필요 = 비가동코드 미기입, 규칙 미일치, 의심·대안, 미등록 다른 물리 고장, 불명확한 공동주어, 같은 명사의 동률 상충 규칙, 부품명만 있는 기록, 정지시간·일자 이상, (설비 기준이 '고장대상 설비'일 때) 고장대상 미기재. 검토필요도 건수·정지시간 집계에는 포함됩니다.
- MES 형식에서 고장대상은 '비가동 코드(중)'의 설비명(예: `1P M/Y …`, `2P I/C …`, `3P F/M …`)입니다. '유틸리티 고장(이상)', '제품불량(설비기인)'은 MES 구조상 코드(중)가 없습니다.

## 설정과 저장 위치

결과 파일: 프로그램 폴더의 `output` (저장 창 기본 위치, 다른 폴더 선택 가능). 폴더에 쓸 수 없으면 `%LOCALAPPDATA%/EquipmentFailureAnalyzer/output`. 보고서에는 회사 기록이 들어가므로 `output/` 내용은 git에서 제외됩니다.

사용자 설정: `%LOCALAPPDATA%/EquipmentFailureAnalyzer/config` (같은 PC·사용자에서 업데이트 후에도 유지)

| 파일 | 내용 |
|---|---|
| classification_config.xlsx | 분류 규칙 ([분류기준 관리]에서 편집) |
| classification_catalog.json | 운영 분류 계층과 카탈로그 버전 |
| normalization.json | 표기 정규화(replacements), 잘린 어미 복원(clause_end_expansions) |
| settings.json | 집계 설정, 고장대상 판정 패턴, 분류 엔진 설정(classifier) |
| equipment_names.json | 라인/설비 코드별 보고서 설비명, 설비군 규칙, 공장·팀 지정값 |
| manual_overrides.json | 행별 수동 보정 (기록 ID 기준) |
| column_overrides.json | 사용자가 확정한 컬럼 매핑 (제목 행 기준) |
| backup/ | 기본값 자동 병합 전 백업 |

번들 기본값: 프로젝트의 `config` 폴더 (이전 기본값 지문: `defaults_history.json`)

업데이트할 때 같은 Windows 사용자의 설정 폴더를 유지하면 기존 수동 보정과 설비명을 보존합니다. 운영 카탈로그 전환 전 설정을 백업하며, 새 목록 안의 사용자 규칙은 유지하고 범위 밖 규칙은 내용·우선순위를 보존한 채 비활성화합니다. 같은 카탈로그의 후속 실행에서는 사용자가 비활성화하거나 삭제한 규칙을 되살리지 않습니다.

전환 중 저장이나 검증이 실패하면 완료로 표시하지 않고 오류를 안내합니다. 원인을 해결한 뒤 다시 실행하면 전환을 재시도합니다. 이전에 만든 보고서는 재분석·재생성해야 새 분류가 반영됩니다.

## 시트 구성

설비관리자가 우선순위 판단부터 이력 확인까지 이어서 볼 수 있도록 기존 18개 시트를 기본 11개로 통합했습니다. 제품 자료가 있는 분석에만 `12_제품교차분석`을 추가합니다.

| 시트 | 설비관리자의 사용 목적 |
|---|---|
| 01_종합현황 | 분석 범위와 전체 건수·정지시간을 확인하고 우선 관리 대상을 선정 |
| 02_설비별분석 | 설비별 손실 비교, 건수·시간 Pareto, 각 설비의 전체 유형순위와 구성비 확인 |
| 03_라인별분석 | 라인별 손실을 비교하고 현장 점검·정비 지원 대상을 선정 |
| 04_유형별분석 | 최종 고장 유형별 건수·정지시간과 Pareto로 개선 과제를 선정 |
| 05_기간별추이 | 월·주·일·연도별 변동을 확인하고 개선 전후 추이를 비교 |
| 06_부품별분석 | 부품별 포함 기록 수와 월별 추이를 함께 보고 예방정비·예비품 검토에 활용 |
| 07_고장이력 | 전체 이력을 정지시간 내림차순으로 확인. 상위 N건을 강조하고 원문·분류 근거를 추적 |
| 08_부품증상상세 | 한 이력 안의 부품·증상·조치를 나눠 확인 |
| 09_검토품질 | 원본 행·원문·분류·부품군·별도 조치·후보로 검토 대기 기록 확인 |
| 10_원본데이터 | 원본 행과 분석 결과를 대조 (MES의 생성·수정 사용자 열은 제외) |
| 11_기준정보 | 분석에 적용한 설비명·공장·팀 설정과 부품 식별 규칙을 확인 |
| 12_제품교차분석 | 제품 자료가 있을 때 제품×유형, 설비×제품, 설비×제품×유형과 제품 Pareto 확인 |

`02_설비별분석`의 유형 구성비는 설비별 고장 기록 기준이며, 전체 분석을 분모로 한 건수·시간 비중도 별도 열로 제공합니다. `06_부품별분석`은 최종 단일 부품이 정해진 고장기록만 집계합니다. 미확정 후보는 실제 부품 건수에 넣지 않으며, 비율의 분모는 전체 고장기록입니다. 부품별 정지시간은 임의로 나누지 않습니다.

통합은 이후 생성하는 보고서에 적용됩니다. 입력 원본과 이미 저장된 보고서는 자동으로 바뀌지 않습니다. 기존 시트별 검수 결과와 권장 열람 순서는 [시트 검수·통폐합 내역](docs/REPORT_SHEET_REVIEW.md)을 참고하세요.
