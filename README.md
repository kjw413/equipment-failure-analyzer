# 설비 고장 분석기 v1.11.0

MES 비가동 내보내기(Excel)를 읽어 고장 기록을 표준 유형으로 분류하고, Excel 분석파일(기본 11개 시트, 제품 자료가 있으면 12개), PDF 최종보고서, 원본 검토표시 사본을 함께 만드는 오프라인 Windows 프로그램입니다. 분류는 로컬 규칙 기반이며 외부 전송이나 LLM을 쓰지 않습니다.

## v1.11.0 분야·부품·증상 분류

- 단일·복수 고장 모두 **대분류=분야 / 중분류=부품 종류 / 소분류=증상**으로 분류합니다. 기존 세부 부품 목록과 별칭은 부품 식별 기준으로 계속 사용합니다.
- `실린더 및 베어링 손상`은 `공압·진공 / 실린더 / 손상`, `기계 / 베어링 / 손상` 두 항목으로 나눕니다. 부품마다 다른 증상이 적혀 있으면 각 부품에 연결합니다.
- `베어링 교체`처럼 조치만 적힌 기록은 `베어링 / 증상 미기재`이며 교체를 별도 조치로 남깁니다. 원문에 없는 마모·파손을 추정하지 않습니다.
- **상세분석 → 부품·증상 분류**에서 나뉜 항목을 한 행씩 확인합니다. 행을 더블클릭하면 해당 원본 이력으로 이동해 단일·복수 분류를 수정합니다. Excel의 **08_부품증상상세**와 PDF에도 부품·증상별 행을 제공합니다.
- 원본 이력 수와 정지시간은 한 번만 집계합니다. 같은 부품의 증상이 여러 개여도 부품별 포함 건수는 한 번이며, 부품·증상 상세에는 정지시간을 반복 배분하지 않습니다.
- 기존 수동확정은 증상을 자동 추정하지 않고 새 구조로 표시하며 원래 보정값은 보존합니다. 새 규칙 파일(schema 5)은 v1.11.0 이상 실행파일 전용입니다.

아래는 이전 버전에서 적용한 변경 기록입니다.

## v1.10.0 규칙 미일치 보완과 판정 정리

- 규칙과 맞지 않는 고장은 비가동코드(중·소)가 비어 있으면 **비가동코드 미기입**, 입력돼 있으면 **규칙 미일치**로 표시합니다(이전 '미분류').
- 고장내용에 부품명이 없으면 작업자가 입력한 비가동코드(소)의 부품명으로 다시 판정합니다.
- 부품 후보가 하나도 없을 때만 쓰는 **nopart** 규칙을 추가했습니다. 제품 걸림·막힘, 제품 낙하, 자재 불량(새 분류 `공정·운전 / 제품·자재`)과 부품 언급 없는 WAGO 에러·통신 이상(제어기(종류 미상))입니다.
- 부품별로 묶었을 때 근거 있는 유형이 하나뿐이면 규칙분류하고, 'A 및 B 마모'처럼 하나의 고장·교체 표현으로 나열한 부품은 복수 유형 조합으로 규칙분류합니다.
- 규칙 파일은 schema 4, 최소 v1.10.0입니다. v1.10.0을 한 번 실행한 PC의 설정은 이전 EXE로 읽을 수 없으므로 EXE를 다시 빌드하세요.

## v1.9.0 화면 구성과 표에서 바로 수정

화면 탭을 **종합현황 / 검토필요 / 상세분석 / 설비별 유형순위 / 부품별 포함 건수 / 월별 부품 추이 / 그래프**로 정리했습니다.
[상세분석] 안에서 설비별·라인별·유형별 분석과 전체 기록 · 수정·교차분석·원본 확인을 선택합니다.
[검토필요]에서는 대·중·소분류를 앞에 배치하고 원본 설비·분류·비고를 함께 볼 수 있습니다.
설비명 변환 설정·분류기준 관리·설정 폴더는 상단 [기준정보 · 설정] 메뉴에 모았습니다.
[파일 · 분석 조건]은 펼치거나 접을 수 있습니다. 파일을 불러오면 펼치고 분석이 끝나면 자동으로 접어 표 영역을 넓힙니다.

[선택 행 수동 수정] 버튼 대신 [검토필요]와 [상세분석 → 전체 기록 · 수정]의 표에서 셀을 더블클릭하거나 F2를 누릅니다.
분류 셀은 계층별 목록에서 선택하며 세 항목이 모두 완성되면 저장합니다. 노란 셀은 선택 중이며 Esc로 취소합니다.
유형조합 셀에서는 단일·복수 분류를 편집하고 적용하거나 취소합니다.
일자·정지시간·고장대상·제품은 입력 후 Enter를 누르거나 다른 셀로 이동하면 저장됩니다.
행의 우클릭 메뉴에서 분류를 편집하거나 분류 보정만 해제할 수 있으며, 그 기록의 수동 보정을 모두 해제할 수도 있습니다.
저장하면 분석표를 갱신합니다. 시간·일자만 고쳐도 분류가 확정되지는 않으며, 보고서 파일에는 다시 생성한 뒤 반영됩니다.

## v1.8.0 운영 분류 목록 적용

편집 가능한 표의 대분류 → 중분류 → 소분류는 제공된 분류 카탈로그를 적용한 선택 목록입니다.
기본 카탈로그는 **대분류 6개·중분류 58개·소분류 237개**이며 기본 부품 규칙 237개를 함께 제공합니다.
이는 배포 기본값의 개수이며, 사용자 규칙의 추가·비활성화·삭제에 따라 개인 프로필의 실제 활성 규칙 수는 달라질 수 있습니다.
상위 분류를 바꾸면 하위 목록이 갱신됩니다. 복수 유형도 [유형 추가]로 행을 늘려 각 계층을
목록에서 선택하고 필요 없는 행을 삭제합니다. 분류명을 직접 입력하지 않습니다.
소분류는 구체적인 부품 종류로 구성하며 마모·파손 같은 현상이나 교체·조정 같은 조치를 붙이지 않습니다.
부품 종류를 원문에서 확인할 수 없으면 해당 부품군의 종류 미상 항목을 사용합니다.
부품명과 고장·조치 조건이 모두 맞아야 자동 후보가 되며, 증상·브랜드명·장치 번호만으로 세부 부품을 추정하지 않습니다.
이전 수동확정값은 해당 기록의 기존값으로 보존하며 새 목록으로 자동 재해석하지 않습니다.

처음 전환할 때 새 기본 규칙을 설치하고 이전 기본 규칙을 퇴역시킵니다. 새 목록 범위 밖의
기존 사용자 규칙은 내용과 우선순위를 보존한 채 비활성화하고, 범위 안의 사용자 규칙은 유지합니다.
기존 수동 보정과 설비명은 유지하며 전환 전 설정을 백업합니다. 같은 운영 카탈로그의 후속 실행에서는
사용자가 비활성화하거나 삭제한 새 규칙을 되살리지 않습니다.

## v1.7.0 복수 고장 조합

실제 독립 고장들의 유형을 조합으로 기록합니다. `모터 + 센서`와 `센서 + 모터`는 같은 조합이며,
`모터 + 체인`과 구분됩니다. 조합별 규칙을 따로 만들지 않습니다. 같은 부품의 대안 후보나
점검만 한 부품을 복수 고장으로 세지 않습니다. `모터 고장 또는 센서 고장`과 같은 대안 표현도 동시 고장으로 합치지 않고 검토합니다.

- 유형조합 셀의 편집 목록에서 [복수 유형]과 구성 유형을 선택하고 [적용]을 누르면 `복수유형확정`으로 저장합니다.
- 조합별 유형·설비·기간 집계는 원본 기록당 1건과 정지시간 1회만 반영합니다.
- [부품별 포함 건수]와 [월별 부품 추이]는 각 구성 유형의 포함 기록을 세고 사용자확정·잠정검토를 구분합니다.
- 부품별 비율의 분모는 전체 고장기록이며 합계가 100%를 넘을 수 있습니다. 부품별 정지시간은 임의로 배분하지 않습니다.

## v1.7.2 규칙 판정 복원

부품·증상 조건에 일치하는 규칙으로 후보 유형을 만들고, 명시된 결정 규칙으로 유형을 정합니다.
제외 조건·부정 표현·예정 정비를 먼저 걸러내며, 원인 규칙, 구체적인 부품명,
고장·교체 근거, 명시적인 인과관계와 MES 부위 단서를 사용해 겹치는 후보를 해소합니다.
해소되지 않은 후보, 명시적인 대안, 독립된 복수 부품·고장은 검토필요로 남기고,
일치하는 후보가 없으면 비가동코드(중·소)가 비어 있으면 '비가동코드 미기입', 입력돼 있으면 '규칙 미일치'로 표시합니다.

- 상세·검토 화면과 Excel에 **분류 판정 사유**, **후보별 규칙·근거**를 표시합니다.
- 사용자확정과 복수유형확정은 자동 판정보다 우선합니다. 시간만 수정하면 분류는 확정되지 않습니다.
- 검토필요도 건수·정지시간에 포함됩니다. 독립 고장은 유형 조합으로 잠정 집계하고 사람이 확정합니다.
- 계층별 목록 선택, 복수 유형 조합, 부품별 포함 건수와 월별 추이는 유지합니다.
- 이전 점수 설정값은 분류에 사용하지 않습니다. 과거 보고서는 바뀌지 않으므로 재분석 후 다시 생성하세요.
- 새 운영 분류 목록과 조건 일치 규칙을 함께 적용합니다. 분류 목록 선택과 자동 판정은 같은 계층을 사용합니다.

검토 건수는 운영 목록의 범위와 부품명·고장 근거, 사용자 규칙·수동 보정에 따라 달라집니다.
새 목록 적용이 검토 건수 감소를 보장하지 않습니다. 변경 이력은 docs/CHANGELOG.md에 있습니다.

## 실행

ZIP을 모두 풀거나 저장소를 내려받은 후 프로젝트 폴더의 **START.bat**을 더블클릭하세요. Python 3.11~3.13 (64-bit)이 필요합니다.
최초 실행은 인터넷 또는 wheels 폴더의 사전 준비 파일로 라이브러리를 프로젝트 폴더의 .venv에 설치합니다. 설치 후에는 오프라인으로 동작합니다.

Python이 없는 현장 PC용: 준비된 Windows PC에서 **BUILD_EXE.bat**을 실행하면 테스트 후 프로젝트 폴더에 **EquipmentFailureAnalyzer_v1.11.0.exe**처럼 버전이 붙은 EXE가 생성됩니다.
버전이 없는 `EquipmentFailureAnalyzer.exe`는 v1.4.0 이하의 이전 빌드입니다. 사내 설치·배포는 IT 정책을 따르세요.

**구버전 실행 차단:** 한 PC의 모든 버전이 같은 사용자 설정을 공유합니다. v1.11.0 이후 규칙 파일(schema 5)은 v1.11.0 이상 전용입니다. 이전 EXE는 새 규칙을 읽지 못하며, 최신 START.bat 또는 v1.11.0 이상 EXE로 실행해야 합니다. 이전 프로그램이 새 분류 규칙을 잘못 해석하거나 기본값 병합으로 바꾸는 일을 방지합니다.

## 사용 순서

Excel 드래그 앤 드롭 / 파일 찾아보기 -> (필요 시) [컬럼 매핑] -> [기준정보 · 설정 → 설비명 변환 설정] -> 분석 -> [검토필요] 표에서 확인·수정 -> [Excel + PDF 생성]

[설비명 변환 설정]의 기본 명명 기준은 **라인 코드(C열)**입니다. 라인별 보고서 설비명을 입력하며, 기존 **설비 코드(E열)** 변환표는 별도로 보존하고 선택할 수 있습니다. 열 위치가 다른 파일은 [컬럼 매핑]에서 라인 코드 열을 지정합니다. 라인 열이 없는 파일은 기존 설비 코드 기준을 사용합니다.
같은 창의 **설비군 규칙**에서 구분자를 `#`로 두면 `A#1(1호기)`, `A#2`를 `A` 설비군으로 묶습니다. 설비군 열에서 개별 값을 지정하거나 구분자를 변경할 수 있습니다. 상단 **설비 분석 기준 → 설비군(이름 기준)**을 선택하면 해당 설비군별로 화면과 Excel·PDF를 집계합니다. 기본 **사용자 지정 설비명** 기준에서는 호기별 이름을 유지합니다.
같은 표의 **공장 / 팀**도 직접 입력할 수 있습니다. 공장 기본값은 원본 라인명 `[공장명]`에서 자동으로 읽으며, 직접 입력한 공장명이 우선합니다. 공장 입력을 비우면 자동값으로 돌아가고, 팀은 직접 지정합니다. 설정은 다음 실행에도 유지됩니다. **설비 분석 기준 → 공장 / 팀**을 선택하면 공장별 또는 공장·팀별로 집계하며, Excel 설정·상세 시트와 PDF에도 반영됩니다.

상단 **공장 필터 / 팀 필터**에서 분석할 대상을 선택합니다. 기본값은 **전체 공장 / 전체 팀**이며, 공장을 선택하면 해당 공장의 팀 목록을 보여줍니다. 미기재 항목도 선택할 수 있습니다. 선택한 공장·팀은 분석 범위·기간·중복 제외 조건과 함께 적용되며, 화면 집계와 Excel·PDF, 원본 사본의 검토표시에 동일하게 반영됩니다. 설비 분석 기준은 집계 단위를 정하고 공장·팀 필터는 분석 대상을 정합니다.

[기준정보 · 설정 → 검토필요 색상 설정]에서 **복수검토 → 규칙 미일치 → 비가동코드 미기입 → 기타** 네 유형의 셀 배경색을 지정합니다. 기타에는 정지시간·일자·고장대상 이상 등 나머지 품질 검토 사유가 포함되며, 기존 검토 판정 기준은 유지됩니다. 저장한 색상은 다음 실행에도 유지됩니다.
[Excel + PDF 생성]은 분석 엑셀, 최종보고서 PDF, `결과이름_원본_검토표시.xlsx`를 함께 저장합니다(원본이 `.xlsm`이면 검토표시 사본도 `.xlsm`). 검토표시 사본은 현재 분석 범위의 검토필요 원본 행 A:X 전체를 한 가지 대표 배경색으로 표시하며, 입력 원본을 덮어쓰지 않습니다. 한 행에 여러 검토 사유가 있으면 위 네 유형 순서에서 가장 앞선 유형의 색상을 적용합니다. 행마다 메모 하나에 모든 사유를 남기며 기존 메모는 보존합니다.

지원: .xlsx/.xlsm. 매크로는 실행하지 않습니다. .xls/암호화 파일은 미지원입니다. 시트나 제목 행을 바꾼 후에는 [시트 읽기]를 누르세요.

CLI: `python analyze_cli.py INPUT.xlsx --output OUTPUT.xlsx [--basis target] [--overwrite]`

라인 이름·설비군 CLI 예: `python analyze_cli.py INPUT.xlsx --output OUTPUT.xlsx --name-source line --set-name "LINE01=A#1" --set-name "LINE02=A#2" --basis group`

공장·팀 필터 CLI 예: `python analyze_cli.py INPUT.xlsx --output OUTPUT.xlsx --factory "서울공장" --team "포장팀"`

## 분류·집계 기준

- 기본은 고장만 집계하며 계획운휴/작업운휴는 제외합니다. 1행=1기록. 시간 미기재를 0분으로 보지 않습니다.
- 생산량/가동시간/실수리시간 없이 고장률·MTBF·MTTR를 만들지 않습니다.
- 유형은 비고에 기록된 부품·증상 조건과 결정 규칙으로 분류하며 원인 확정이 아닙니다. 후보 충돌·명시적 대안·복수 고장은 검토필요로 남깁니다.
- 검토필요 = 비가동코드 미기입, 규칙 미일치, 해소되지 않은 후보, 명시적 대안, 복수 고장, 정지시간·일자 이상, (설비 기준이 '고장대상 설비'일 때) 고장대상 미기재. 검토필요도 건수·정지시간 집계에는 포함됩니다.
- MES 형식에서 고장대상은 '비가동 코드(중)'의 설비명(예: `1P M/Y …`, `2P I/C …`, `3P F/M …`)입니다. '유틸리티 고장(이상)', '제품불량(설비기인)'은 MES 구조상 코드(중)가 없습니다.

## 설정과 저장 위치

결과 파일: 프로그램 폴더의 `output` (저장 창 기본 위치, 다른 폴더 선택 가능). 폴더에 쓸 수 없으면 `%LOCALAPPDATA%/EquipmentFailureAnalyzer/output`. 보고서에는 회사 기록이 들어가므로 `output/` 내용은 git에서 제외됩니다.

사용자 설정: `%LOCALAPPDATA%/EquipmentFailureAnalyzer/config` (같은 PC·사용자에서 업데이트 후에도 유지)

| 파일 | 내용 |
|---|---|
| classification_config.xlsx | 분류 규칙 ([분류기준 관리]에서 편집) |
| classification_catalog.json | 운영 분류 계층과 카탈로그 버전 |
| normalization.json | 표기 정규화(replacements), 잘린 어미 복원(clause_end_expansions) |
| settings.json | 집계 설정, 고장대상 판정 패턴, 분류 엔진 설정(classifier) |
| equipment_names.json | 라인/설비 코드별 보고서 설비명, 설비군 규칙, 공장·팀 지정값 |
| manual_overrides.json | 행별 수동 보정 (기록 ID 기준) |
| column_overrides.json | 사용자가 확정한 컬럼 매핑 (제목 행 기준) |
| backup/ | 기본값 자동 병합 전 백업 |

번들 기본값: 프로젝트의 `config` 폴더 (이전 기본값 지문: `defaults_history.json`)

전환 중 저장이나 검증이 실패하면 완료로 표시하지 않고 오류를 안내합니다. 원인을 해결한 뒤 다시 실행하면 전환을 재시도합니다. 이전에 만든 보고서는 재분석·재생성해야 새 분류가 반영됩니다.

## 시트 구성

설비관리자가 우선순위 판단부터 이력 확인까지 이어서 볼 수 있도록 기존 18개 시트를 기본 11개로 통합했습니다. 제품 자료가 있는 분석에만 `12_제품교차분석`을 추가합니다.

| 시트 | 설비관리자의 사용 목적 |
|---|---|
| 01_종합현황 | 분석 범위와 전체 건수·정지시간을 확인하고 우선 관리 대상을 선정 |
| 02_설비별분석 | 설비별 손실 비교, 건수·시간 Pareto, 각 설비의 전체 유형순위와 구성비 확인 |
| 03_라인별분석 | 라인별 손실을 비교하고 현장 점검·정비 지원 대상을 선정 |
| 04_유형별분석 | 고장 유형·복수 유형 조합별 건수·정지시간과 Pareto로 개선 과제를 선정 |
| 05_기간별추이 | 월·주·일·연도별 변동을 확인하고 개선 전후 추이를 비교 |
| 06_부품별분석 | 부품별 포함 기록 수와 월별 추이를 함께 보고 예방정비·예비품 검토에 활용 |
| 07_고장이력 | 전체 이력을 정지시간 내림차순으로 확인. 상위 N건을 강조하고 원문·분류 근거를 추적 |
| 08_부품증상상세 | 한 이력 안의 부품·증상·조치를 나눠 확인 |
| 09_검토품질 | 검토 대기 기록을 먼저 확인하고 아래의 데이터품질·분석 조건을 점검 |
| 10_원본데이터 | 원본 행과 분석 결과를 대조 (MES의 생성·수정 사용자 열은 제외) |
| 11_기준정보 | 분석에 적용한 설비명·공장·팀 설정과 부품 식별 규칙을 확인 |
| 12_제품교차분석 | 제품 자료가 있을 때 제품×유형, 설비×제품, 설비×제품×유형과 제품 Pareto 확인 |

`02_설비별분석`의 유형 구성비는 설비별 고장 기록 기준이며, 전체 분석을 분모로 한 건수·시간 비중도 별도 열로 제공합니다. `06_부품별분석`은 각 부품을 포함한 기록 수이므로 복수 고장 1건이 여러 부품에 포함될 수 있으며, 두 표의 건수를 더하지 않습니다. 부품별 정지시간은 임의로 나누지 않습니다.

통합은 이후 생성하는 보고서에 적용됩니다. 입력 원본과 이미 저장된 보고서는 자동으로 바뀌지 않습니다. 기존 시트별 검수 결과와 권장 열람 순서는 [시트 검수·통폐합 내역](docs/REPORT_SHEET_REVIEW.md)을 참고하세요.
